## 补充 2：T11.2 细粒度 RBAC——用户管理 API + 三条硬规则 + 空角色越权漏洞修复

- **auth 用户管理 API**（admin-only，Bearer 二次验签不信任网关转发头——auth 是认证本体，自我校验更严）：列表/创建（BCrypt）/启停/重置密码/角色替换/删除；护栏 = 不能停用/删除自己、不能动掉最后一个 active admin。AdminPage 新增「用户与角色管理」卡（创建/角色分配/重置密码/启停/删除），用户管理「待接」清账。
- **三条硬规则落地**：①审阅关裁决权（workflow 既有 @PreAuthorize，补注解反射守护测试）②KB 写权限 = admin——kb.py 13 个写端点从 require_writer 收紧，**designer 从此不可写知识库**（GAP P2-5 口径，消费/建模不受影响）③系统管理门禁——`/llm/provider/reload` 原本**完全无鉴权**（审查新发现），补 require_admin。
- **漏洞修复**：authz.py require_writer/require_admin 对「角色头缺失/为空」一律放行（`if roles and not ...`）——直连 py-engine 不带角色头即可越权写。改为缺失即 403；gateway 对合法 JWT 恒注入 X-User-Roles，正常流量零影响。
- 验证：py 全量 302 passed（+6 RBAC 用例）；auth 11 + workflow 1 新测试；容器栈真实生命周期（创建 reviewer→403 门禁→停用→登录 403→重置密码→升 admin→登录 200→删除）。
- 坑归档：①UserEntity 缺 createdAt/updatedAt setter（插入时间戳靠 DB default 的隐式假设被显式赋值需求打破）；②纯 Mockito 单测中 ASSIGN_UUID 不生效 → insert 后 id 为 null，verify 用 any() 而非 anyString()；③Git Bash 中文 JSON 老坑再发威（displayName 中文导致 curl 负载 GBK 乱码，服务端 400——验收负载一律 ASCII）；④MyBatis-Plus ASSIGN_UUID 生成 32 位无横线 hex，PG uuid 列接受。
