## 补充 1：T12.2 E1 正向联动——参数双向联动的另一半落地（+ Docker daemon 卡死恢复）

- **实现**：`POST /cad-agent/sessions/{sid}/parameters/{pid}/update`（总体设计 §8.2 :700 承诺的入口，仅 paused@gate2）→ IR2 追加新版本（value + derivation 原地同步复用 sync_derivation）→ 定向失效 IR3/IR4/IR5 → a3_task 重派 → A3 重新建模（geometry_link 正向联动）→ A4 → 自动重挂 gate2 复审（零 Java 改动）。biz V16 `cad_param_updates` 记 origin/depth。
- **变更抑制三件套**（系统实施方案 :279 Origin Lock/Max Depth=3 的务实落地）：①depth 链计量——forward=1、反向 confirm 顺延（T11.3 confirm 现也记链 origin=reverse_confirm），>3 → 409；②反向事件挂起 = 提案确认制（本来就不自动回写）；③单飞行窗口 = 仅 paused@gate2 可发起，天然串行。乒乓不成环的根因：反向 confirm 只重派 A4 不重派 A3（几何即真相，T11.3 决策）。
- 验证：单测 5 例（含非 gate2 409/参数不存在 404/深度上限）；e2e test_e1_forward_e2e.py 40.9s 全闭环（改参 100→140 → 重建模 → 复审 → 批准 → completed → depth=1 留痕）。首轮 e2e 断言过严（种子会话无 IR4/IR5 却断言三者全失效）——markInvalidated 返回实际失效类型，断言修正为「以已存在快照为准」。
- **Docker daemon 卡死事故**（首次实发）：py 镜像构建挂 50min+（往常 8min），`docker version` 10s 超时——daemon 整体僵死。处置：PowerShell 脚本杀 Docker 进程 + `wsl --shutdown` + 重启 Docker Desktop（脚本 C:\tmp\restart_docker.ps1 可复用）；25 容器 restart 策略自动恢复，PG 走 WAL 崩溃恢复后数据完好（413 会话核对）。教训：构建挂超 2 倍历史时长即怀疑 daemon 而非重试；`timeout` 包 docker 探测是低成本判据。
