### 补充 1：T9.1 uvicorn「连接建立但无响应」挂死——根因定位与防御性修复 ✅（ZCode）

- 背景：2026-09-19 全站审查期间实发（HANDOFF 待决事项首位）——连接建立但无响应、堆积约 50 连接、重启恢复、根因未查。PHASE-009 首个任务。
- 探索事实（修正任务书假设）：py-engine `api/` 全部路由为同步 `def`（0 个 async），跑在 Starlette/AnyIO 默认 **40 线程**的线程池上——原假设「async 路由内混同步 IO」不成立，真实嫌疑是**线程池耗尽**。
- 根因结论（机制复现，A-16 如实口径）：`tests/load/hang_repro.py`（synthetic 模式：子进程加载真实 `api.main.app` + 注入慢同步端点与旧版同步 healthz 复刻）。实测（本机，100 并发 × 同步 sleep 10s）：

  - 120 线程档（修复后默认）：两者均 ≤0.03s。
  - 判定：机制成立，与 2026-09-19 现场（前端轮询无退避持续放大）特征吻合；原始现场未在真实栈复放，此为等效机制复现。未涉及架构调整，不补 ADR。

### 补充 2：T9.2 CSR 约束满足率落地 ✅（ZCode）

- 口径（写死于 `a4_validation/agent.py` run() 注释 + PHASE-009 §2.2 + 前端 tooltip，三处同文案）：CSR = 通过/(通过+违反)×100，两位小数；计数对象 = formula 复算、standard 符合性核对、CHK-GEO-NUM 几何数值复核（产出确定性判定的检查）；warning/info 不计分母；结构完整性错误（悬空引用/特征重复/产物缺失/退化）不计入（属产物完整性，由 overall=fail 体现）；无有效检查 → `csr=null`。

### 补充 6：T9.6 缓存键修订——供应商标识入键（e2e 可重复性实测教训）✅（ZCode）

- 现象：四条 e2e 首轮回归 2 失败——phase2 的 A3 三轮修复后仍 `StdFail_NotDone: MakeSolid`（上次运行的失败产物被钉死复用）；kb_pipeline 断言 `vector+graph` 级别缺失（测试陈旧，2026-09-26 3e41439 引入的合法级）。
- 根因：LLM/codegen 缓存键只含 model+messages/IR2 指纹，**不含供应商标识**——mock e2e 每次随机端口起 mock server（provider 不同），但缓存键相同 → 命中上次运行的响应（含失败脚本），e2e 失去可重复性。Redis 实测清出 107 个 llm 键 + 3 个 codegen 键污染。
- 修复：`llm_cache_key`/`codegen_cache_key` 增加 provider_tag = `{base_url}|{model}`——同供应商同请求才命中，换供应商/mock 重启自然 miss；真实环境 provider 稳定不受影响。单测同步（同 messages 换 provider 必 miss 两断言）+ kb e2e 断言补 `vector+graph`。
- 教训入档：缓存键语义 = 「同上下文」而非「同请求文本」；凡影响产物生成的环境维度（供应商/模型版本）都应入键。

## 补充 11：压测返修——broker 重投致闸门状态机卡死（T10.2/T10.3 途中发现）

- **现象**：基线第 1 轮（真实 LLM）A2 完成后会话卡在 `paused + current_stage=A2`，驱动方永远等不到 gate1。
- **根因链**：worker 与 RabbitMQ 连接抖动（"Connection to broker lost"）→ `task_acks_late` 语义下已成功的 A2 被 broker 重投 → 第二次执行 0.49s（IR2 v2 重复快照，无害）→ 其内部 `update_stage(A2)` 把 pauseAtGate 刚写的 `current_stage=gate1` **覆写回 A2** → 第二次 STAGE_DONE 回调触发 `pauseAtGate`，乐观更新条件 `eq(running)` 不满足抛 409 → 状态机卡死。
- **修复**（workflow/SessionService，压测返修依据任务书 §4.1）：①STAGE_DONE 的 A2/A4 分支检测「已 paused 且已在对应闸」幂等返回；②`pauseAtGate` 乐观条件放宽为 `running|paused 且 current_stage≠gate`——paused+A2 的覆写态可重挂闸门自愈，已在目标闸则幂等返回现态（不再抛 409）。旧用例 `pauseConflictSurfaces409` 断言的旧契约按新语义改写为幂等/自愈两用例，workflow 35 用例全绿；重建镜像复跑基线。
- 重投产生的重复执行本身是 acks_late（崩溃不丢任务）的已知代价，IR 快照按版本追加天然幂等；闸门幂等补齐后整条链自洽。

## 补充 13：T10.2 压测执行——限流阈值校准回调（又一个实测缺陷）

- **校准干跑暴露**：50 VU 实际请求率 ~52 req/s，PHASE-009 保守限流（RL_WF 50/s、RL_PY 20/s）全部顶穿 → 429 被计为错误（4.3%–17.6%，超 <1% 口径）。429 是预期降级行为，但正常设计并发（50 用户）不应被限流——限流防滥用，不防目标负载。
