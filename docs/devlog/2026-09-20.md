### 补充 40：会话删除外键顺序修复（用户实测踩中）✅（ZCode）

- **现象**：删除带裁决记录的会话 500——`update or delete on table "ir_snapshots" violates foreign key constraint`。此前实现先删 ir_snapshots 后删 review_records/trace_chains，而两表均以 `ir_snapshot_id` 外键引用快照（V4 建表），父表先删即 FK 违约。昨晚实机验证没暴露是因为测试会话均无裁决记录（mock 单测的 mapper 也不校验 FK）
- **修复**：SessionCleanupService 删除顺序按外键依赖重排——review_records → traceability_chain → ir_snapshots → design_sessions（子表先删）；新增 `childrenDeletedBeforeSnapshots` 单测用 Mockito InOrder 断言调用顺序（防回归），workflow 累计 25 全绿
- **实机验证**：合成场景（垃圾会话 + SQL 直插 review_records/traceability_chain 各 1 行引用其 IR0 快照）→ API 删除成功，三表级联计数 1/1/1 ✓
- 顺带确认：溯源链表实际表名 `traceability_chain`（TraceChainEntity @TableName 映射），与直觉命名不同——合成 SQL 踩了一次
