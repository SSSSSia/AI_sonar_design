### 补充：镜像拉取失败与加速方案（T0.2 验收阻塞项分析）

**现象**：`docker compose up` 全部镜像 4.9s 内 `Interrupted`，最终报 `pull access denied for minio/minio, repository does not exist or may require 'docker login'`。

**根因**：国内网络直连 `registry-1.docker.io` 不通；"pull access denied / may require login" 是 Docker Hub 连接失败时的误导性报错，与登录无关。quay.io（etcd）同为并行拉取被殃及。

**修复**：
1. compose 全部镜像改为支持加速前缀：Docker Hub 镜像用 `${DOCKER_MIRROR:-}` 前缀、quay 用 `${QUAY_MIRROR:-quay.io/}` 前缀（变量带结尾斜杠，留空 = 直连官方源，不影响已有行为）
2. `.env.example`/`.env` 增加注释态变量说明
3. 推荐方案：Docker Desktop Settings → Docker Engine 配 `registry-mirrors`（全局生效，compose 无需改动）；备选：.env 启用 DOCKER_MIRROR/QUAY_MIRROR

**教训**：Docker 拉取报 "access denied / repository does not exist" 时先查网络连通性（尤其国内环境），不要真的去 docker login。

### 补充 5：MinIO 供应链根治——切换 Chainguard digest 固定镜像（ADR-002）✅

用户要求把"生产前重新评估"提前解决。方案比选（详见 ADR-002）：
- elestio/minio：RELEASE.2025-09-07，**不含 CVE-2025-62506 修复**，弃用
- alpine/minio：加速源 403（源级封锁），单维护者，弃用
- 源码自建：完全可控但维护重，留作 fallback
- **采用：cgr.dev/chainguard/minio 按 digest 固定**（sha256:83b4a2d9…）——正规厂商、0 CVE、58MB、非 root，cgr.dev 直连可用

落地要点（两次踩坑）：
1. 镜像 entrypoint 就是 /usr/bin/minio（无 docker-entrypoint 包装），compose command 必须只传参数（["server", "/data"]），不能再写 "minio server ..."
2. 旧卷数据属主是 root（elestio 以 root 运行写入），Chainguard 非 root FATAL 无法写后端 → 新增 `minio-volume-init` 一次性服务幂等 chown，两个 minio 服务 depends_on service_completed_successfully

验证：9/9 healthy + 真实凭据 S3 全回环（alias/mb/cp/cat/rb）通过。健康检查改用官方推荐 `mc ready local`。上游已移除 Web Console（2025-06），业务 MinIO 不再映射 9001。

**踩坑 4 个（重要，均已写入代码注释/HANDOFF）**：
1. `Map.of()` 不接受 null 值——celery v2 embed（callbacks 等）为 null，NPE；用 HashMap
2. **api 进程里 `shared_task.delay()` 绑到 Celery 默认 app**（消息进默认 `celery` 队列、路由/DLX 全失效）——必须 `celery_app.set_current()/set_default()`
3. **DLQ 放 task_queues 会被 worker 自动订阅 → 死信再消费回环**——DLQ 用 worker_ready 信号单独声明，worker 永不消费
4. 失败任务默认是 ack 不进 DLQ——需显式 `raise Reject(requeue=False)`（业务任务重试上限耗尽后同路径）
