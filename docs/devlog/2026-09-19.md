### 补充 30：用户首轮人工验收反馈修复——失败重试 + UI 明显缺陷 ✅

用户实测反馈：漏洞多、交互不人性化、UI 不协调/标签超出父标签、失败后无法重启、审阅关糙、裁决历史吐 JSON、会话 ID 不该裸吐。本轮修「明显 bug」，系统性交互/UI 审查留给下一轮（用户另开窗口换模型执行）。

- **失败可重试（核心）**：`failed` 原为终态。新增 `PipelineEvent.RETRY`（failed→running），转移表/状态机配置/单测三处同步（互证测试覆盖）；`SessionService.fireEvent` 转移前校验 `current_stage∈A1..A5`（防先转 running 再派发失败的脏状态），转移后按阶段重派任务并推送 WS 进度。worker a1–a5 **任务开始即 `update_stage`**——原实现仅在成功后标记，导致「A2 运行中失败」误记为 A1、RETRY 会派错棒（顺带修正运行中时间线显示）。前端失败会话顶部红色 Alert + 「重新执行 {stage}」按钮（admin/designer）
- **失败根因澄清**：两个失败会话（d50db0d5 / c4e54e0f，均 A3 失败）是验收当时 LLM 瞬时故障的连锁——A1 降级（如实标注）→ A2 降级 0 参数 → gate1 仍放行 → A3 硬失败。本轮实测 LLM 连通正常
- **原始需求溢出**：降级 IR1 的 objectives 是 `{dimension:'原始需求', value:<整段需求>}`，审阅页用 AntD Tag 渲染（nowrap）→ 单行溢出卡片。IR1 卡改定义式两列布局（与总览页一致）+ `overflowWrap:anywhere`
- **裁决历史吐 JSON**：根因是 `review_records.annotations` 存复合负载 `{annotations, trace_id, reviewed_ir, rework_stage, invalidated}`（insertRecord 历史设计）。前端 `annotationsText` 拆包只显示批注正文；新增 `ReviewAnnotation` 组件把机器字段归一为可读副行（审阅对象 IR2 v1，回退 A2，失效 N 份下游快照）；ReviewTab/ReportTab 两处裁决历史表统一替换。trace_id 不外显（仍经溯源链反查）
- **会话 ID**：头部改前 8 位 mono 短 id + 复制按钮（点击复制完整 id）
- **降级警示（审阅关太糙的最小修复）**：ReviewTab 在 gate1 空 IR2 时红 Alert「建议驳回回退 A2，直接批准会在 A3 产生无效模型」；降级 IR1 卡加黄色 Tag、总览页加横幅。A1 降级 `missing_items` 去噪：降级原因只说一遍（首项），其余为纯维度名（test_t13_a1 断言兼容）
