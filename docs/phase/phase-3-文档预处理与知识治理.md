## 1. 硬性要求（宪法 §6，验收逐条核对）

1. 上传支持 PDF / Word / Excel / Markdown / TXT；上传即建档（来源、格式、时间、状态），前端可见入库进度；
2. 解析保留**页码/章节位置**（T1.3 的 `段落N` 级引用届时升级）；
3. 分块策略可配置（章节优先、重叠可调），chunk 携带 `doc_id + location`；
4. 结构化抽取按本体 Schema（P3 §7.2），抽取结果人工可预览（不必等构建完）；
5. 索引构建异步任务：进度可查、失败可重试（有上限，A-13）；
6. 增量更新：只处理变动文档；实体冲突/冗余提示，不静默覆盖；
7. 文档删除同步清理 chunks/实体来源标记；图谱不能删的标 `deprecated`；
8. **诚实红线**：实体/关系数量、来源文档列表 UI 可见；禁止把单案例知识库包装成领域知识库（A-16）。

## 2. 任务分解

### T3.1 文档上传与解析

- **要点**：`POST /api/v1/kb/documents` 上传（类型/大小白名单，宪法 §10.4）→ MinIO 原文件桶；解析器按格式路由（MinerU / PP-Structure，OCR 为可选插件、失败降级纯文本并标注，D-14）；OCR 上下文受限时 max_tokens 显式约束。
- **DoD**：五格式各一真实样例解析通过且带位置信息；扫描件 OCR 降级路径实测；解析失败不中断服务。

### T3.2 清洗分块 + 结构化抽取 + 索引构建 + 增量

- **要点**：清洗（去噪/表格文本规整）→ 可配置分块 → LLM 按本体 Schema 抽取实体/关系（人工预览 API）→ GraphRAG 索引构建 + Milvus 向量入库（`POST /api/v1/kb/build` 异步任务）；增量更新只处理 diff 文档。
- **DoD**：构建任务进度可查/失败重试有上限；增量构建实测（改一个文档重建时间显著小于全量）；抽取预览可人工修正。

### T3.3 公式/约束/军标库管理（首样入库）

- **要点**：公式/约束/军标三类库的录入/启停/可信度分层 API 与存储（5.14）；LLM 供应商配置管理一并补齐（5.16，含 T1.2 预留的 llm_providers 管理 API + api_key 脱敏序列化）。**首样**：用 `towed_array_cad_knowledge.txt` 全流程入库（上传→解析→分块→抽取→索引→在检索三级中命中图谱级）。
- **DoD**：首样全流程走通且 `/knowledge/status` 显示图谱级命中；军标库空态如实"待补"；公式入库后 A4 校验（阶段 2）可引用。

### T3.4 图谱可视化数据接口

- **要点**：力导向全图（限流采样）+ 邻域子图两类查询接口；节点带来源 doc_id（可反查文档）。
- **DoD**：真实 KB 上邻域查询毫秒级返回；节点-文档互跳数据完整。

## 3. 顺序与风险

T3.1 → T3.2 → T3.3（首样）→ T3.4。风险：MinerU/PP-Structure 本机部署重（对策：先非 OCR 格式全通，OCR 插件化后置）；GraphRAG 全量构建耗 LLM tokens（对策：首样单文档先行，tokens 消耗记录在案）。
