## 1. 发布检查清单（宪法附录 A，逐项执行留痕）

- [ ] roadmap 全部任务状态"完成"且文档回填
- [ ] 端到端冒烟通过（标准样例需求 → STEP，`tests/e2e/`）
- [ ] 审阅关①②走查：通过流 + 回退流均验证
- [ ] 文档上传 → 知识库构建全流程真实文档跑通
- [ ] 前端核心页面人工走查（工作台/审阅/参数表/知识库/交付物）
- [ ] `.env` 未入库；全库日志/文档/截图无密钥泄露（含历史提交抽查）
- [ ] 无未提交改动，`main` 已推送
- [ ] 版本号与 tag 符合 §8.3（`v0.x.y`：x=阶段里程碑，y=阶段内迭代）

## 2. 执行流程

1. 汇总各阶段文档「验收记录」——存在"条件通过"遗留项的先清账或走 ADR 豁免；
2. 逐项执行 §1 清单，每项记录执行人/日期/证据（命令输出或截图路径）；
3. **人工验收优先**：清单不自动部署、不自动打 tag；全过并经用户确认后才执行 `git tag v0.1.0` + push tag；
4. tag 信息写清本版本包含的阶段/任务范围（阶段 0–5 全部）。

## 3. 风险与对策

| 风险 | 对策 |
|---|---|
| 遗留项拖到验收期集中爆发 | 各阶段验收"条件通过"项即时登记 roadmap 备注；阶段 5 先清账 |
| 演示环境与开发环境漂移 | 验收在干净 `git clone` + `docker compose up` 上执行一轮 |
| 密钥历史泄露 | 验收期跑一次全历史 secret 扫描（gitleaks 或等价） |
