## 2. 专项 B：阶段 15 最小可信建模闭环（P1 起，自研）

**先于完整范例库产品化**：B1 管理增加可维护性，无法消除孔径误配与身份交换；先交一个“参数→几何→语义检查”的可验收纵向切片。验收锚点为外部审查案例 02（大偏差仍需识别）、03（孔径不得替代为同值宽度）、04（部件交换身份不互换）。依据：`docs/reviews/2026-10-02-外部审查核验.md:109`–`:111`；`docs/phase/phase-14-可信度加固.md` §7。

### 2.1 设计前置（P1，联合评审）

1. 映射契约与身份语义一起设计：对象语义 ID、参数 ID、尺寸类型、单位、测量依据、容差、模型版本及未匹配/歧义状态。`param_mapping` 等名称均为拟定字段，IR3 当前并未具备。
2. 新模型优先显式对象 ID/命名与执行期元数据，并和实测几何互证；LLM 自报映射不能单独作为真值。
3. 旧 STEP 使用几何/拓扑候选匹配但允许不确定，不能承诺“改成质心/拓扑稳定键就解决身份”。对称同尺寸、部件交换、旋转、拆分/合并均需反例。
4. 同期评审 §3 批准组合契约，避免模型/报告链稳定后再补版本语义；契约兼容与治理约束不变。

依据：`py-engine/agents/a3_cad/agent.py:221` 当前 F/SEG 按分段索引编号；`py-engine/cad_engine/geometry_inspect.py:405` 当前按最长轴排序；`py-engine/agents/a3_cad/geometry_link.py:45` 当前 bbox 偏差贪心，均不足以证明稳定语义身份。

## 3. 专项 C：批准版本组合与审阅/导出深化（P1 设计，P2 内核）

**当前事实**：`java-platform/workflow/src/main/java/com/sonarcad/workflow/session/ReviewService.java:77` 的 gate2 被审快照为 IR3，`:125` 记录单快照 ID，`:137` 的 expectedSnapshotVersion 可省略；`py-engine/api/cad.py:176`、`:208` 的 Word/PDF 分别读取 latest IR2/IR3/IR4。当前不是完整批准组合冻结。

1. **C-0 组合契约（P1）**：确定批准时 IR2/IR3/IR4 的确切快照 ID/版本/哈希和依赖有效性；若正式文档含 IR1 未决项或其他上下文，也记录相应版本。明确 fail/incomplete、人工例外与缺失项的批准/发布规则，不把 gate2 批准等同“几何全合格”。
2. **C-1 事务与正式导出内核（P2）**：主仓在批准操作内记录版本组合并做并发条件校验，导出按组合读取、校验有效性和产物哈希，不能到导出时才猜“当时 latest”；读取/生成期间版本变化的处理也需定义。工作稿导出与正式批准版分别标注状态、版本清单与未决项；正式版未满足规则返回明确原因。
3. **C-2 读侧/视图（P2 后段）**：聚合检查表、全参数 diff、未决项、全链版本清单及来源；Word/PDF 共用同一数据组合。只读 UI 不承担批准判定。
4. **参考 F**：若学生最终选题 5/F，可借鉴依赖分析、反例和视图设计，再自行实现主仓诊断；不要求其使用真实审批包，不依赖其实现生产事务，也不把模拟依赖当真实批准证据。

验收：旧批准后更换参数/模型/报告、旧页面并发裁决、无有效报告、历史版本导出、工作稿/正式版标识、Word/PDF 数据一致；按明确政策允许或拒绝，不只检查前端按钮。依据：上述源码锚点；`docs/phase/phase-14-可信度加固.md` §7；OPT-001 §3.7.6。
