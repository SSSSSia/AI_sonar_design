## 1. 重点专项 A：参考代码范例库治理（N-1 / GAP-001 P3-1）

> 现状与证据全文见 [OPT-001 §1](优化改进与毕设选题清单.md) 与 GAP-001 P3-1：单范例硬耦合、无管理入口、非拖曳阵需求静默退化、无沉淀回哺。本节给方案对比与推荐路线。

### 1.1 方案对比

| 方案 | 内容 | 工作量 | 优点 | 局限 | 判定 |
|---|---|---|---|---|---|
| **A · 止血最小治理**（文件态保留） | ①范例目录外置：`app_config` 加 `SONARCAD_REF_DIR` 环境变量（沿用 `os.environ.get` 惯例），`CodeSearchService` 构造注入（唯一调用点 `agents/a3_cad/agent.py:73`）；②`_file_cache` 加 mtime 失效——**免重启加范例**；③选型透明化：IR3 契约加法加可选 `reference_used`（filename/score/type_matched，match_info 已有），会话总览展示「本次使用范例」——**静默退化变显性**；④catalog.yaml 字段规范补充 | ~0.5–1 天 | 立即缓解「加范例=改代码+发版+重启」与「退化无感知」两个最痛的点；零迁移零新表 | 仍无 UI/版本/多用户管理 | **立即执行** |
| **B · 产品化三层**（P3-1 完整方案） | B1 管理闭环（表+桶+CRUD+前端 Tab+数据迁移）；B2 检索式选范例（embedding top-k 多范例注入）；B3 沉淀闭环（gate2 批准→脱敏→质量门→pending→人工确认） | B1 ≈ 1 迭代；B2/B3 可与毕设题 1 协同 | 从根上解决管理与造血；检索与沉淀是研究增量 | B2/B3 依赖 embedding/沙箱链路联调 | **分期执行（推荐主路线）** |
| **C · 并入知识库体系**（范例作 kb 文档类型） | 范例脚本当文档走 kb 上传/分块/检索管线 | 最小复用 | 零新表 | 语义不合：代码范例需要**沙箱执行、AST 常量剥离、片段行号索引**，与文档分块/抽取/TTL 管线完全不同构；RBAC 与审计边界也不同 | **不采用**——仅 B2 的 embedding 管道复用 KB 供应商调用 |

### 1.2 推荐路线（A → B1 → B2/B3 协同 + B4 并行）

- **第 0 步（本迭代内，P0）**：方案 A 全量——外置目录 + 缓存失效 + IR3 `reference_used` 透明化 + catalog 规范。A 是 B 的前置不冲突项（B1 落地后文件态转 fallback）。
- **B1 管理闭环（自研，下一迭代，P0）**：
  - Flyway V20 `ref_scripts` 表（编号/名称/声呐类型标签/关键词/描述/object_key/sha256/片段索引 JSONB/状态/版本；V19 已应用、V20 曾预留未落）+ MinIO `ref-scripts` 桶（ADR-002 桶管理先例）；
  - CRUD 端点挂 `/api/v1/kb/references/**`（**复用 kb 网关路由零改动**）+ 审计规则 `kb.ref.*`（`api/audit.py` `_RULES`）；
  - 知识库页新 Tab（照 RegistryTab 惯例）；
  - 一次性迁移脚本：catalog.yaml + 拖曳阵脚本入库；
  - `CodeSearchService` 数据源切到表（对外 `select_reference` 接口不变）；**库不可用退包内文件态并如实标注来源**（A-14 降级，方案 A 的目录保留为 fallback）。
- **B2 检索式选型（与毕设题 1 协同）**：学生按 OPT-001 §3.6 插件接口交付检索包（需求文本+top_k → 排序范例）；**主仓侧承接**：`select_reference` 加 `top_k`、`agent.py:251-268` 的参考代码 prompt 块改多范例拼接、embedding 索引构建任务挂 worker、评测跑 e2e 三档实验。无人接则自研（工作量中）。
- **B3 沉淀闭环（自研内核 + 可协同）**：主仓侧=gate2 批准事件钩子（挂 `cad_agent/service.py` finalize 单点或 ReviewService 事后事件）+ Celery 候选任务 + pending/确认状态机（复用 A5 模式）；学生可做脱敏算法（AST 常量剥离→参数化模板）与质量门策略研究。
- **B4 范例数据建设（非代码，最长周期，立即启动协调）**：向导师/领域渠道收集 2–3 个其他类型声呐的高质量 CadQuery 孪生脚本——**B 方案真正的瓶颈是写范例而不是写管理**；并行策略：本系统 gate2 批准产出经 B3 逐步积累。此项需要用户/导师协调，技术侧无阻塞。

### 1.3 验收与回退

| 步 | 验收 | 回退 |
|---|---|---|
| A | 免重启新增范例生效；总览页显示本次范例来源与匹配分；非拖曳阵需求可见「退化为默认范例」提示 | 单 commit revert |
| B1 | CRUD+Tab+迁移回归绿（py/vitest/towed e2e）；检索走表数据 | CodeSearchService 数据源开关回文件态 |
| B2 | 三档实验报告（无/错域/对域范例：生成成功率、修复循环次数、CHK-GEO-NUM 超差率） | 关闭向量选型回关键词 |
| B3 | gate2 批准脚本 → 候选 → 确认入库 → 下次同类需求检索命中 | 候选不确认即无副作用 |

## 2. 重点专项 B：建模映射架构（阶段 15 核心链，自研）

> 立账来源：PHASE-014 §7（外部审查问题 3+7 + 振幅条款）；OPT-001 题 7 已标高耦合例外——**仅「语义检查器规则包」子题可外包**，其余主仓自研。

分期（每期独立可回退，验收锚定回归案例 02◐/03✗/04✗）：

1. **B-1 结构化参数注入**：IR2 parameters 全量 JSON 块注入 A3 prompt（替代纯文本转述）+ 振幅例外条款治理（`prompts.py:129-133`）——最小且独立，先行；
2. **B-2 参数→特征映射契约**：IR3 加法加可选 `param_mapping`（LLM 结构化输出 + 沙箱执行期对象命名/元数据登记双通道互证）；
3. **B-3 SEG 稳定标识**：`geometry_inspect.py` 分段锚定从最长轴排序改拓扑/质心稳定键，跨版本对位（E1 提案对位同步受益）；
4. **B-4 语义检查器**：孔径/壁厚/长度三族规则——**注册位主仓实现，规则族可接毕设题 7 学生构件**。

约束：每期 towed + cad_tune e2e 全绿才前进；IR3 契约只增可选字段（A-12 旧快照兼容）。

## 3. 专项 C：审阅/导出深化——主仓侧内核

OPT-001 题 4 学生做视图组件（检查表/diff/组件集），**主仓侧自研**：①冻结导出门判定内核（IR2/IR3/IR4 latest ∈ gate2 批准版本组合，复用 T14.6 版本条件模式）；②未决项数据通路（IR1 `missing_items` → `docgen/export_docx.py` 新章）；③导出聚合读侧端点。无人接题 4 时全量自研（工作量中）。

## 4. 专项 D：对话式需求解析——条件自研

若毕设无人接：先做 MVP（单轮「预检-追问」：提交前对需求文本跑缺失项预检，列出追问清单，确认后拼装成稿走 `POST /sessions`——复用 IR1 missing_items 语义，A1 零改动）；全量 chat 层后置。有人接则只做成稿文本对接。

## 5. 专项 E：视觉元数据资产库（自研，未派题）

UI-3 后续立项原文：MinIO 新桶（design-assets）+ Flyway 表（类型/关联项目·会话/上传者/标签）+ 上传端点 + 项目/会话详情挂图与缩略图；审计与 RBAC 按 T13.4/T13.1 惯例。
