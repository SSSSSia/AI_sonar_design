## 一、项目背景与目标

### 1.1 研究背景与痛点

声呐装备的参数化设计当前依赖三类工具，各有不可弥补的局限：

```
传统 CAD 工具（CATIA / UG）：
  精确、可靠、符合国军标——但完全依赖工程师手动配置参数
  问题：新入职设计人员培养周期 3-5 年；资深专家知识难以传承

现有 AI 生成工具（Text2CAD 等学术方案）：
  能从自然语言生成几何模型——但参数完全靠 AI 隐式推测
  问题：无工程知识库；无物理约束验证；无合规性保障，不敢直接用

知识管理系统（企业知识库 / 文档检索）：
  能检索工程文档——但知识是"死的"，公式不可计算
  问题：检索到约束公式后，系统不会执行它；验证仍靠人工
```

**核心空白**：没有任何现有系统能同时做到：①基于工程知识图谱的**可计算约束推理**；②AI 生成与规则验证的**双层闭环**；③设计人员与系统之间的**交互式参数精化**。

**已有原型验证**：项目组已完成一套可运行的原型系统（自然语言需求 → STEP 三维模型）。原型运行表明：当参数推断与代码生成混在同一环节、缺少独立的约束推理时，系统对工程知识的执行并不稳定（例如传输缆配色多次被生成为深灰，而非知识库规定的红色），部分参数只能标注为"估算"。根因不在于 AI 完全不会算，而在于缺少一个独立的约束引擎，对工程公式、参数可行范围和知识缺口做显式的执行与核查。这正是本系统要解决的核心问题，也是本建议书的直接动机。

### 1.2 系统定位

本系统不是一个"更好的 CAD 软件"，也不是"更聪明的文档检索系统"，而是：

> **一套以知识图谱为底座、以约束推理为核心、以人机协作为模式的声呐参数化设计辅助系统。**

它的价值不在于"替代工程师"，而在于：
- 把资深专家的设计经验沉淀为系统可计算的知识图谱；
- 让 AI 在工程约束的"围栏"内生成方案，而不是自由发挥；
- 把工程师从"反复核算参数是否正确"的重复劳动中解放出来，专注于创造性判断；
- 持续积累每一次设计决策，让系统越用越强。

### 1.3 设计目标

本系统在工程定位上以**"多Agent分布式协同 + 符号约束围栏"的双层闭环架构**为骨架，将大模型的语义理解能力与工业级拓扑求解器的精确计算能力严格解耦。其建设目标如下：

| 能力 | 说明 | 建设节奏 |
|---|---|---|
| **可计算** | 知识库里的工程公式由底层求解引擎真正执行，而不只是文字描述；任何参数取值与公式求解 100% 由计算引擎驱动，严禁大模型介入数值计算 | 首批交付 |
| **可解释** | 推理过程可追溯，知识缺口（系统不会算的地方）清晰可见 | 首批交付 |
| **可审计** | 每个参数值都能追溯其来源公式或规范条款 | 首批交付 |
| **闭环验证** | 自动生成 + 自动校验形成双层闭环，参数不合规能定向修复而非整体重试 | 首批交付 |
| **功能边界防腐** | 各 Agent 职责严格隔离（需求理解/知识检索/约束推理/代码生成/演化验证），互不越界，互不交叉计算 | 首批交付 |
| **中间产物精化** | 将《系统设计说明书》《声学性能计算书》《参数约束求解报告》等中间产物作为一等公民暴露，支持参数级微调与文档级批注两类人工反馈，驱动局部增量重算 | 首批交付 |
| **人机协同审查** | 配套生成完整设计文档，工程师审查后可就任意环节反馈，系统据指定向修订并重新生成 | 首批交付 |
| **交互精化** | 设计人员在三维视图点击部件即可反向定位参数并增量调整 | 后续扩展 |
| **持续学习** | 积累修复与决策数据，逐步学习更优的修复与推理策略 | 远期演进 |

### 1.4 设计原则

1. **以知识推理为主、AI 生成为辅**：参数取值由约束推理引擎按公式与范围算出，AI 仅在需求理解、代码生成、知识缺口兜底等受限位置介入，且产出可追溯。
2. **精确优先**：对工程公式（如指向性指数 `DI = 10·lg(N)`）采用精确代入计算，不做近似简化，保证参数准确。
3. **有界终止优于完美**：系统必须在有限步内给出结果——要么输出满足约束的方案，要么如实降级输出最优候选并说明原因，绝不死循环或静默出错。
4. **知识可计算优先于知识规模化**：先让现有知识"能算"，再追求知识覆盖规模的扩大。

## 三、系统总体架构与边界定义

本系统打破了传统AI生成工具"单向流、纯文本生成"的局限，独创了**"多Agent分布式协同 + 符号约束围栏"的双层闭环架构**。系统通过明确的功能边界，将大模型的语义理解能力与工业级拓扑求解器的精确计算能力进行严格解耦，实现从自然语言需求到 GJB 合规 STEP 三维模型的端到端可靠转化。

### 3.1 动态三维协同架构（三轴协同）

系统构建了空间上分层、时间上有环的动态协作体系，通过三个轴向协同工作：

1. **管控轴（会话调度中枢）**：以"有向有环状态机"为核心，维护全局设计上下文，统筹调度 Agent 间的状态跳转与异常回溯，是系统的"中枢大脑"。
2. **执行轴（智能体协作链）**：由需求理解、知识检索、约束推理、代码生成、演化验证五大专业级 Agent 顺序接力。各 Agent 间通过标准中间表示（IR数据流）互联，前后职责清晰，互不越界。
3. **算力轴（底座求解引擎）**：以可计算知识图谱为底座，通过区间算术（AC-3）与符号解析双轨制驱动，将"死文档"转化为"活公式"，为执行轴提供确定性的刚性约束计算。

### 3.2 系统核心边界与数据流（Functional Boundaries）

为确保系统的工程高可靠性，系统各核心组件划分了严格的"防腐层（Boundary Prefabs）"，大模型（LLM）在系统中仅作为"语义到符号的翻译器"与"代码结构的组装器"，任何参数取值与公式求解 100% 由底层计算引擎驱动，严禁大模型介入数值计算：

| 组件名称 | 功能边界（What it DOES） | 严禁介入的边界（What it DOES NOT） | 核心输入 → 输出 |
| :--- | :--- | :--- | :--- |
| **Agent1 需求理解** | 提取自然语言中的声呐性能、结构、材料指标。 | 严禁推导几何参数，严禁直接生成 CAD 代码。 | 用户文本 → 显式需求 JSON (IR-1) |
| **Agent2 知识检索** | 依据显式需求，在图谱及向量库中检索对应的 GJB 规范和声呐公式。 | 严禁对公式进行求解、代入或赋值。 | 需求 JSON → 原始知识/公式实体 (IR-2) |
| **Agent3 约束推理** | 驱动双轨求解器（符号/区间）计算出无冲突的参数区间和代表点。 | 严禁推测几何拓扑，严禁输出任何 3D 渲染逻辑。 | 原始知识 → 完备参数与收敛域 JSON (IR-3) |
| **Agent4 代码生成** | 依据参数结果与 Few-Shot 模版，在受限的安全沙箱中组装生成 CadQuery 脚本。 | 严禁盲目修改参数数值，必须严格继承 Agent3 的计算输出。 | 约束参数 + 模版 → 纯净 CAD 脚本 (IR-4) |
| **Agent5 演化验证** | 在隔离沙箱中执行脚本，编译导出模型并完成几何干涉检查、体积/质量核算。 | 严禁直接修改代码，只允许抛出带有异常坐标和约束ID的结构化报告。 | CAD 脚本 → 拓扑验证报告 (IR-5) |

### 3.3 系统核心三大闭环机制（含中间产物人工精化回路）

系统原生设计了三层动态回路，将自动化机器自愈与人工深度评审融为一体，赋予系统极强的自我修正与降级自愈能力：

- **【回路一：知识补充自愈闭环】（Agent3 → Agent2 → Agent3）**：当约束推理引擎发现计算矩阵存在自由度缺口（Gap）时，自动反向触发精准检索，补充公式边界，直至推理闭合。
- **【回路二：方案修正自愈闭环】（Agent5 → Agent3 → Agent4 → Agent5）**：演化验证若在底层编译或干涉检查中拦截到硬性错误，回溯至约束推理智能体，采取"单调收缩策略"重新锁死物理安全域并定向重构代码，杜绝盲目重试。
- **【回路三：双轨动态人工精化回路】（用户 → 中间产物矩阵 → 局部增量重算）**：系统不仅交付 3D 模型，更将伴生的**《系统设计说明书》、《声学性能计算书》、《参数约束求解报告》**等中间产物作为一等公民全面暴露。工程师审阅时可进行两类反馈：
  1. **参数级微调**：在 3D 视图或参数单中直接修改数值，系统仅对约束图受影响的局部子图进行增量传播。
  2. **文档级批注（语义级修正）**：工程师可直接对系统说明书或计算书中的特定章节/选型提出**批注式意见**（如："吸声材料应替换为特种聚氨酯"）。系统自动将文本批注作为增量上下文反向路由至 Agent2 或 Agent3，驱动系统重新生成受影响的局部方案与中间文档，实现"文档生成 → 人工批注 → 语义解析 → 局部重算 → 产物动态更新"的协同闭环。

## 四、关键技术

### 4.1 声呐设计知识库内容体系

系统的知识库涵盖声呐装备设计的完整知识体系，分为三类，分别对应不同的工程资料载体：

| 类别 | 性质 | 典型载体 | 在系统中的作用 |
|---|---|---|---|
| **规范与标准**（约束类知识） | 系统必须满足的硬性要求 | 国军标、国标、设计规范 | 提供参数的硬约束边界（如外径上限、灵敏度下限），约束推理据此校验 |
| **结构与设计知识**（机理类知识） | 描述"如何设计" | 设计说明书、机理文档 | 提供可计算的工程公式（如指向性指数、传播损失），约束推理据此求解 |
| **历史设计方案与图纸**（经验类知识） | 沉淀工程经验 | 历史三维模型、参数表、设计案例 | 提供参考取值与典型设计模式，辅助参数选型 |

知识库建设需要合作方的数据支持：首批系统采用经过整理的参考案例知识验证方法可行性；第二阶段接入合作方提供的真实规范标准、脱敏工程资料与历史设计图纸，是双方合作的核心内容之一。系统支持 PDF、Word、Excel、图片、Markdown 等多种格式的资料入库与结构化解析。

### 4.2 可计算的约束推理

这是本系统区别于普通 AI 生成工具的核心能力。知识库中的每一条公式都标注了"这是什么类型的约束、该怎么算"，约束推理引擎据此把文字公式真正变成可计算的结果：

- **等式类公式（直接算）**：如指向性指数 `DI = 10·lg(N)`、传播损失 `TL = 20·lg(R)`、阵列长度 `L = N × d`，系统将已知参数精确代入公式，直接算出结果参数的值，不做近似简化。
- **不等式类约束（算范围）**：如外径不超过 27mm、灵敏度不低于 -195dB、阵元间距不小于两倍阵元半径，系统据此算出每个参数可以取的范围（可行域），再从中选定一个合理取值（默认取范围中点，稳健且可复现；也可取最接近历史案例的值）。
- **量纲感知**：几何量（毫米/米级）、声学量（分贝/赫兹级）、结构量（兆帕级）自动分流到对应的计算方式，避免单位混淆。

推理过程全程留痕：每个参数值记录由哪条公式算出、取值策略是什么、依据来自哪份资料，保证结果可追溯、可审计。当某参数在知识库中既无公式、又无范围约束时，系统不会硬猜，而是明确标注"此处需工程师确认"，绝不糊弄。

### 4.3 自动校验与闭环修复

模型生成后，系统自动执行多层校验，确保结果真正可用：

- **几何检查**：自动核查部件之间是否存在干涉、尺寸是否越界、装配是否合理。这部分检查逻辑由系统统一注入，不由 AI 生成，避免 AI 写错检查或漏检导致死循环。
- **约束复核**：对照知识库中的工程约束，逐条检查生成结果的参数是否满足（如总重、外径、灵敏度等是否合规）。
- **定向修复**：校验不通过时，系统不是整体推倒重来，而是精确定位是哪条约束、哪个参数出了问题，回到约束推理环节收紧该参数的取值范围后重新生成。这种"定向修复"比整体重试高效得多，也是系统能在有限步内收敛的关键。

校验结果同样可追溯：哪条约束满足、哪条违反、违反后如何修复，全部记录在案，形成完整的设计决策链。

### 4.4 声呐设计参数体系

系统内置完整的声呐设计参数体系，涵盖四大类，约束推理按参数类型分别处理：

| 参数类 | 示例 | 处理方式 |
|---|---|---|
| **结构参数** | 外径、阵列长度、阵元间距、最小弯曲半径 | 范围约束（算可行域） |
| **声学性能参数（核心）** | 工作频率、指向性指数、传播损失、灵敏度 | 按约束结构：等式直接算，不等式算范围 |
| **环境适应性参数** | 工作深度、温度盐深、抗压等级 | 范围约束（算可行域） |
| **可靠性指标** | 平均无故障时间、密封等级、振动等级 | 范围约束（算可行域） |

首批系统聚焦拖曳线列阵声呐，后续逐步扩展至其他声呐类型。

## 五、系统功能设计

### 5.1 全自动生成模式

设计人员输入自然语言需求（目标探测距离、工作频率、部署深度、检测阈值等），系统自动完成"需求理解 → 知识检索 → 约束推理 → 代码生成 → 校验"全流程，一次性输出完整的设计成果，包括：

- **三维模型**（STEP 格式）；
- **技术方案文档 / 设计说明书**（结构组成、设计思路、关键参数）；
- **参数计算书**（每个参数的取值、所依据的公式与来源，支持反查）；
- **设计评审报告**（哪些约束满足、哪些违反、如何修复）；
- **知识缺口清单**（哪些参数缺乏依据、需工程师确认）。

这是系统首批交付的核心功能。

### 5.2 设计文档生成与人工审查反馈

系统生成的全部文档与模型均面向工程师审查使用。工程师审阅后，可就任意环节向系统提出反馈意见，例如：某参数取值不合理、需补充或修改某项约束、某处几何结构需调整、设计目标需变更等。

系统接到反馈后，会自动定位问题对应的智能体与参数，回到相应环节重算或修订，并重新生成受影响的文档与模型，形成"**生成 → 审查 → 反馈 → 修订**"的人机协同闭环：

- 参数取值问题 → 回到约束推理重算；
- 公式或知识有误 → 回到知识检索与知识库修正；
- 几何结构问题 → 回到代码生成调整；
- 设计目标变更 → 回到需求理解重新分解。

整个反馈过程全程留痕，每次修订自动保存版本，支持历史回溯与前后对比。这一机制让系统不只是"一次性出图"，而是能与工程师持续协作、逐步收敛到满意方案的设计伙伴。

### 5.3 交互式精化模式（后续扩展）

设计人员在三维视图中点击任意部件，系统自动定位该部件对应的参数、展示当前值与可调范围，并提供参数滑块。调整参数后，系统只重算受影响的部分（增量更新），实时更新三维视图与参数对比，支持版本回退。

### 5.4 系统集成接口（后续扩展）

提供标准化接口，支持与企业现有 CAD/PLM 系统集成，输入结构化需求，输出三维模型与参数结果。

### 5.5 核心模块职责

| 模块 | 职责 | 输入 → 输出 |
|---|---|---|
| 需求理解 | 自然语言 → 结构化设计目标与子任务 | 需求文本 → 设计目标 |
| 知识检索 | 从知识库调取相关公式、约束、案例 | 设计目标 → 知识集合 |
| 约束推理 | 按公式与范围算出全部参数取值 | 知识集合 → 参数方案 |
| 代码生成 | 据参数方案生成三维建模代码 | 参数方案 → 建模代码 |
| 校验 | 执行代码、检查约束、定向修复 | 建模代码 → 校验结果 |

## 六、远期发展方向

在核心系统稳定运行、积累足够设计决策数据之后，系统将沿以下方向持续演进：一是**知识图谱规模化**，覆盖更多声呐类型（侧扫、主动阵等）与更丰富的设计场景；二是**智能化优化**，基于历史修复与决策数据，引入策略学习机制，让系统自动学会更优的参数修复与推理路径，进一步提升收敛效率与设计质量。这些方向属于长期研究性工作，将在核心系统交付后稳步推进，不影响首批与第二阶段的核心交付。

## 七、技术选型

| 技术选型 | 选择 | 选择理由 |
|---|---|---|
| 流程编排 | 自研状态机 | 轻量可控，便于定制校验回路与降级逻辑 |
| 知识图谱 | GraphRAG + 公式边 | 适合声呐领域知识组织，支持语义检索与公式执行 |
| 等式约束求解 | 符号精确代入（SymPy） | 保证工程公式计算精度，避免近似误差 |
| 不等式约束求解 | 区间传播（自研） | 与知识图谱遍历紧密集成，算出参数可行域 |
| 三维建模 | CadQuery（Python） | 开源、支持 STEP 导出、可注入校验逻辑 |
| 大语言模型 | DeepSeek 系列 | 成本可控，中文工程术语处理良好，支持结构化输出 |
| 知识来源 | 参考案例 + 合作方真实资料 | 首批用参考案例验证方法，第二阶段接入合作方规范与工程资料 |
