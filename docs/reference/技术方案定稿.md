## 2. 九项关键技术路线

### 2.1 IR 契约驱动的多 Agent 固定管线与人在回路三道关

- **问题**：LLM 自由编排不可控、不可复现；长链路生成错误会向下游累积。
- **方案**：流程顺序由编排层（Java 状态机）写死，LLM 无权决定"下一步调用谁"（A-01）；Agent 之间不互调，只通过六份 JSON Schema 契约（IR0–IR5）+ 编排层传递（A-03/A-04）；每个 Agent 职责单一且有负面清单（A-02，如 A3 不改参数、A4 只出报告）；在方案后、出图后、知识沉淀后设**三道人工审阅关**，未通过走局部回算而非整链重跑（A-11/A-12）。
- **实现落点**：`contracts/ir/`、`java-platform/workflow/.../statemachine/`、`py-engine/agents/`、`py-engine/ir_contract.py`（产出侧 jsonschema 校验）。
- **现状**：✅ 全链路 e2e 验证（真实 LLM 全链 7/7，PHASE-014 §5）；契约加法演进已实证向后兼容（IR4 三态升级不破坏旧快照）。

### 2.2 参数溯源四分类与四件套

- **问题**：LLM 生成内容"看上去对"但无据可查；军工设计要求每个数值可还原出处。
- **方案**：IR2 每参数强制携带 `source_type ∈ {formula, case, standard, estimated}` + `source_ref` + `derivation` + `trace_id`（A-06）；来源类型决定下游校验方式与可信度分层；trace_id 贯通五类步骤（取值/变换/校验/沉淀/裁决），支持 API 反查上下文（E2）。
- **实现落点**：`py-engine/agents/a2_scheme/agent.py`、`py-engine/storage/trace_store.py`、`TraceController.java`。
- **现状**：✅ 完整落地；溯源链作为交付物随报告归档。

### 2.3 可计算合规校验链（"LLM 不算数"）

- **问题**：合规核对若交给 LLM 判断，结论不可信也不稳定。
- **方案**：A4 校验**纯确定性、零 LLM**：①公式类参数由 solver 按**注册表符号**做 SymPy 精确代入复算（A2 阶段取值即同源）；②案例类走区间传播；③军标类按条目判定表达式 SymPy 安全求值做符合性核对（适用性与来源解耦：对全部参数按 applies_to 核对）；④估算类重点复核；⑤几何特征与参数数值复核（CHK-GEO-NUM，容差 2%）。v0.7 引入**校验状态学**：overall 三态（pass/fail/incomplete）+ severity 四级（error/warning/info/unverified）+ CSR + coverage 覆盖率——**应检未检不再显示通过**。
- **配套**：`solver/units.py` 单位统一模块（长度/频率/电平/速度/无量纲五族；20mm=2cm=0.02m 同归一值；未知单位/范围字符串显式 `UnresolvableQuantity` → "未验证"，不猜不取首数）；`solver/deps.py` 会话内依赖图（公式依赖级联重算 + A4 复算输入优先取参数快照而非推导文本）。
- **实现落点**：`py-engine/agents/a4_validation/agent.py`、`py-engine/solver/{formulas,intervals,standards,units,deps,recompute}.py`、`contracts/ir/ir4.schema.json`。
- **现状**：✅ 落地并经外部审查 17 条验收案例回归（13 ✅）；军标核对能力就绪、真实 GJB 条目待授权（库空如实"待补"）。

### 2.4 参数化 CAD 与几何真实化

- **问题**：LLM 生成 CAD 代码常见几何错误（画错间距/缆长）却自称正确；生成物与参数脱节。
- **方案**：范例双信号匹配（按声呐类型检索参考实现）→ LLM 生成 CadQuery 脚本 → 多层静态校验（语法/完整性/建模模式）+ 确定性自动修复（有界 3 轮）→ 子进程沙箱执行（300s 硬超时）出 STEP → **geometry_inspect 从 STEP 实测提取特征**（多体 B-rep 零镶嵌/单体半径剖面）→ 特征与参数自动联动 → A4 数值复核闭环（ADR-003"特征真实化优先"，否决 vision-LLM 自证路线）。
- **实现落点**：`py-engine/agents/a3_cad/agent.py`、`py-engine/cad_engine/{reference,validators,sandbox,geometry_inspect}.py`、`agents/a3_cad/geometry_link.py`。
- **现状**：✅ 实机验证有效（改造前 LLM 画错的间距/缆长静默通过，改造后被 CHK-GEO-NUM 捕获为 error——PHASE-007 验收记录）。

### 2.5 CAD 交互微调：薄插件 + 后端大脑

- **问题**：自动生成的模型需要人工精修；重型 CAD 内核无法搬进浏览器，商用 CAD 二开成本高。
- **方案**：FreeCAD（开源 OCC 内核）薄插件做"手脚"——登录换 JWT（零凭据）、3D 视口、工具执行；py-engine `cad_agent` 做"大脑"——ReAct 文本协议推理，工具调用经 `cad_tune_tool_calls` 表**长轮询**下发插件执行（180s 服务端超时兜底），每轮上传真实 STEP → 几何实测 → IR3 追加版本；v0.7 加目标锁定（编辑作用于既定主实体，缺失回退最大体积并如实标注 target_fallback）与产物版本化（按代对象键 + sha256，定稿即失效下游校验/知识快照）。
- **实现落点**：`clients/freecad-plugin/SonarCADLink/`、`py-engine/cad_agent/`、`java-platform/biz`（cad_tune_* 三表）。
- **现状**：✅ 协议与链路 e2e 闭环（mock LLM 44s 用例）；插件真机 13 步冒烟清单就绪、待用户 FreeCAD 环境联调（A-16 如实）。

### 2.6 E1 参数双向联动与依赖重算

- **问题**：文档参数与 CAD 模型两处维护必然失一致；改一个参数后下游公式参数需要同步。
- **方案**：**正向**（文档→CAD）：审阅关①驳回回环 + 会话内参数更新入口；`solver/deps.py` 依赖图定位下游公式参数级联重算（直接更新 + 「依赖重算」修订留痕）；Origin Lock 变更抑制（发起方原子锁 + 传播深度上限 3，超深 409）防环形震荡。**反向**（CAD→文档）：微调轮几何 diff 提案 → 人工确认 → 同参多轮合并取最新（落败 superseded）→ 按符号精确同步推导记录 → IR2 新版本 + 下游失效 → 自动重挂 gate2 复审。
- **实现落点**：`py-engine/cad_agent/param_proposals.py`（merge_by_param / sync_derivation / cascade_dependents）、`py-engine/solver/deps.py`、`py-engine/api/cad_agent.py`。
- **现状**：✅ 双向齐备（v0.4 反向、v0.5 正向、v0.7 依赖重算与提案正确性加固）；依赖边按符号别名会话内现算，零数据库迁移（D14-7 决策）。

### 2.7 知识库体系：三层分类 + 五级降级检索 + 多库路由

- **问题**：设计依据分散于文档/图谱/向量多种形态；任一检索基础设施故障不能中断设计主链路。
- **方案**：知识库按 RAG/GraphRAG/混合三型组织（文档↔库多对多）；入库管线 parsers（PDF/Word/TXT/MD/Excel/图片）+ OCR + 分块 + LLM 结构化抽取（pending 人工确认）+ 三库构建；检索**五级降级链**：GraphRAG SDK local → basic（可选）→ 自建 Neo4j 实体层 → Milvus 向量（可配重排序扩量截断）→ 文本关键词，降级轨迹对上游可见（A-14）；会话建会话手选库或 Agent 依需求文本**自动路由**（选库先于检索定序，v0.7）；检索缓存键含范围语义（unscoped / scoped:文档集）防跨库污染。
- **实现落点**：`py-engine/knowledge/{sdk,service,build_index,import_corpus}.py`、`py-engine/kb/`、`py-engine/worker/tasks.py`（A1 自动选库）、`py-engine/storage/cache.py`。
- **现状**：✅ 实测规模：4 文档 / 439 chunks / 2939 条确认抽取 / 单库 518 实体；检索 P95 1.3s（graph 级命中）。

### 2.8 双后端解耦与编排可信性

- **问题**：业务编排（事务/权限/状态）与 AI 算力（LLM/CAD/求解）技术栈天然异构，耦合则互相拖死。
- **方案**：Java 平台层与 Python 算力层经**手写 Celery protocol v2 消息**（Java TaskPublisher 直投 RabbitMQ，Python worker 消费，7 队列按阶段隔离全配 DLQ）+ 共享存储（PG/MinIO）交换产物；Python worker 无状态、结果写共享存储不回调业务逻辑；状态机推进用乐观并发（WHERE status=当前值，冲突 409）；闸门回调幂等 + 自愈（压测实测发现的重投卡死缺陷修复）；WS 五类消息契约（task_progress/log/review_request/ir_updated/cad_tune_updated/alert）+ JWT 握手 + 指数退避重连 + HTTP 对账兜底。
- **实现落点**：`java-platform/workflow/.../mq/TaskPublisher.java`、`py-engine/worker/celery_app.py`、`contracts/ws/ws-message.schema.json`。
- **现状**：✅ 50 并发 × 30min 压测通过（§3）；水平扩展路径验证（加 worker 副本即扩容）。

### 2.9 可信运维底座

- **内容**：①可观测——Prometheus 双通道指标（API /metrics + worker :9101）+ 4+1 条核心告警（建模超时/检索延迟/缓存命中率/队列长度等，触发证据存档）+ Grafana/Loki 日志分流（审计语义独立留存）；②容灾——备份/恢复脚本 + 演练（GraphML 1473 节点快照回滚验证），双活留生产（ADR-005）；③安全——LLM 出站脱敏（占位回填）、供应商热切换 + 失败转移、vLLM 私有化切换手册、供应链 digest 固定；④审计——独立审计表四侧插桩 + 审计中心。
- **实现落点**：`deploy/docker-compose.yml`（monitoring profile）、`py-engine/observability/`、`docs/ops/vLLM切换手册.md`、`java-platform/auth`（审计查询）。
- **现状**：✅ 开发环境全栈运行（29 容器）；ELK 生产替换、双活实施按生产口径立账。
