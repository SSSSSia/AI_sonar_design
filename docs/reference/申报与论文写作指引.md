## 1. 项目一句话与三段式叙事

**一句话**：面向声呐装备设计全流程，以参数化 CAD 为核心、知识图谱增强检索为可计算依据，建成"需求解析 → 方案生成 → CAD 出图 → 合规校验 → 知识沉淀"五步闭环的智能辅助设计系统，三道人工审阅关把关、参数级全链溯源，同步输出设计方案文本（Word/PDF）、STEP 三维模型、建模脚本、校验报告与溯源链。

**三段式叙事**（适用于摘要/创新点开篇）：

> 系统按"**能算 → 算准 → 算完查**"三道关组织可信性设计：**能算**——五个智能体按固定管线接力，需求进、方案文档与三维模型出，全程人在关键节点把关；**算准**——大模型不直接产生数值，公式类参数由符号计算引擎精确求解，校验由确定性引擎复算，几何特征从三维模型实测反提，杜绝"自说自话"；**算完查**——每项检查显式区分"通过/未过/应检未检"，每个参数可溯源至知识与依据，全部关键操作独立审计留痕，结论可还原"由谁、何时、依据什么作出"。

## 2. 创新点提炼（问题 — 方案 — 差异化 — 证据）

> 每条按"四段式"组织，可直接改写进申报书创新点栏或论文"主要工作/创新点"节；证据列给出可验收的代码/文档/报告出处。

### 创新点 1：契约驱动、人在回路的可解释设计智能体流水线

- **问题**：LLM 自由编排导致流程不可复现、错误向下游累积，难以用于严肃工程设计。
- **方案**：五个智能体按固定管线由状态机编排（LLM 无流程决定权）；智能体间以六份 JSON Schema 中间表示（IR0–IR5）为唯一交互契约，产出侧运行时校验；在方案、出图、知识沉淀三个节点设人工审阅关，驳回只做局部回算并按依赖批量失效下游快照（不可变版本化）。
- **差异化**：相比"单体 LLM 工作流"，流程确定性、产物可版本回退、人工裁决可冻结版本（乐观版本条件拒绝陈旧审批）。
- **证据**：`contracts/ir/`；`java-platform/workflow/.../statemachine/`；ARCH-001 §4/§5；宪法 A-01~A-05/A-11/A-12。

### 创新点 2："LLM 不算数"的可计算合规校验与校验状态学

- **问题**：合规核对交给大模型判断，结论不可信、不稳定，也无法通过军工验收。
- **方案**：校验引擎纯确定性零 LLM：公式参数 SymPy 符号精确复算、案例参数区间传播、军标条目表达式安全求值、几何特征数值复核（2% 容差）；参数值带机器可读单位统一换算（未知单位显式"未验证"而非猜值）；提出**校验状态学**——结论三态（通过/未过/**不完整**）、风险四级（含"应检未检"级）+ 约束满足率 + 验证覆盖率，使"没查"不可能伪装成"通过"。
- **差异化**：国内公开报道的 CAD 智能设计系统多将校验交给模型自评；本系统把"算"与"查"全部收口到可复现的确定性引擎，并首次将"应检未检"状态化为可信度缺陷而非沉默通过。
- **证据**：`py-engine/solver/`（formulas/intervals/standards/units/deps）、`py-engine/agents/a4_validation/agent.py`、`contracts/ir/ir4.schema.json`；TECH-001 §2.3；外部审查验收案例 13/17 通过（`docs/reviews/2026-10-02-外部审查核验.md`）。

### 创新点 3：几何真实化——生成模型自我验证闭环

- **问题**：LLM 生成 CAD 代码的几何错误（间距、缆长画错）无法靠代码审查发现，模型"自称正确"。
- **方案**：CAD 产物不采信模型自述——从 STEP 成品**实测提取几何特征**（B-rep 解析），特征与设计参数自动联动比对，超差生成结构化 error；配套有界自动修复循环与子进程沙箱执行。
- **差异化**：以"产物实测"替代"模型自证"（明确否决 vision-LLM 自检路线，ADR-003），实现生成物与参数表的数值级闭环。
- **证据**：`py-engine/cad_engine/geometry_inspect.py`、`agents/a3_cad/geometry_link.py`；PHASE-007 验收（改造前错误静默通过 → 改造后被捕获）；TECH-001 §2.4。

### 创新点 4：薄插件 + 后端大脑的交互式 CAD 微调架构

- **问题**：自动生成的三维模型需人工精修；商用 CAD 二次开发成本高，Web 端三维交互能力不足。
- **方案**：FreeCAD 薄插件仅承担视口与工具执行（零凭据、零 pip 依赖、纯 HTTP），"大脑"置于服务端（ReAct 推理、工具经长轮询外包插件执行、每轮上传真实 STEP 实测并版本化）；编辑目标锁定主实体，回退如实标注。
- **差异化**：LLM 推理在服务端可治理（脱敏/审计/限流），插件保持极薄可替换；微调产物与主流程同契约（IR3 追加版本 + 审阅关②审定稿），不产生"体外循环"。
- **证据**：`clients/freecad-plugin/SonarCADLink/`、`py-engine/cad_agent/`；ADR-004；ARCH-001 §4.5。

### 创新点 5：参数双向联动与依赖感知的受控重算

- **问题**：设计文档与三维模型两处维护必然失一致；局部参数修改后下游公式参数人工同步易漏。
- **方案**：正向（文档→CAD）参数更新按会话内公式依赖图级联重算（直接更新 + 修订留痕），配变更抑制（发起方原子锁 + 传播深度上限）防震荡；反向（CAD→文档）几何偏差生成确认提案，多轮同参合并取最新、按符号精确同步推导记录，确认后自动重挂审阅关。
- **差异化**：双向闭环 + 依赖感知重算 + 全程留痕，而非简单的"参数替换"；零数据库迁移的会话内依赖图实现易于演进。
- **证据**：`py-engine/solver/deps.py`、`py-engine/cad_agent/param_proposals.py`；ARCH-001 §4.6；TECH-001 §2.6。

### 创新点 6（工程底座，可选报）：面向可信交付的双后端平台

- **要点**：Java 业务平台与 Python 算力层经消息队列解耦（手写 Celery 协议互操作），状态机乐观并发 + 死信隔离 + 幂等闸门；50 并发压测错误率 0.0148%、端到端中位 9.2 分钟（≤15 分钟目标）；监控告警/日志分流/备份演练/独立审计齐备。
- **证据**：TECH-001 §2.8/§2.9/§3。

## 5. 申报书常用段落模板

> 以下段落为可直接改写的底稿（~150–250 字/段），【】处按申报书口径替换；引用数字须与 §3 汇总表核对。

**【系统概述】**：本项目面向声呐装备设计周期长、知识复用难、合规核对依赖人工的现状，研制了一套智能辅助设计系统。系统以参数化 CAD 为核心，采用"业务编排与 AI 算力分离"的双后端架构（Java 平台层负责流程编排、权限与审计，Python 算力层承载五个设计智能体、约束求解与三维建模引擎），打通"需求解析 → 方案生成 → CAD 出图 → 合规校验 → 知识沉淀"全流程闭环，在方案、出图、知识沉淀三个关键节点保留人工审阅，输出符合制图规范的 STEP 三维模型与设计方案文档。

**【技术路线】**：系统以六份 JSON Schema 中间表示契约贯穿全流程，智能体间不直接调用、只经契约与编排层交互，保证流程确定性与产物可版本回退。合规校验采用确定性引擎：公式类参数由符号计算引擎精确复算，案例类参数区间核对，军用标准条目经表达式安全求值做符合性判定，几何特征从三维模型实测反提并与设计参数数值比对（容差 2%）；校验结论分为通过/未过/不完整三态，并输出约束满足率与验证覆盖率，杜绝"应检未检"被当作通过。

**【创新性】**：一是"LLM 不算数"的可信生成机制——大模型仅承担理解与组织，一切数值由代码计算与复算，几何真实性以产物实测验证，从机制上消除模型幻觉对设计结论的污染；二是参数级全链溯源——每个数值强制携带来源类型、依据、推导过程与溯源标识，可反查至知识条目，满足军工设计可验收、可追责要求；三是人在回路的知识沉淀闭环——设计经验经人工确认回写知识图谱，检索能力随使用持续增强。

**【技术指标】**（示例口径，按申报书要求裁剪）：端到端设计闭环 ≤15 分钟（实测中位 9.2 分钟）；知识检索 P95 ≤4 秒（目标 ≤4 分钟，余量 180 倍）；50 并发持续负载错误率 ≤0.02%；几何特征复核容差 2%；测试资产 550+ 用例（含 7 条真实大模型端到端验证）。

**【可行性/工作基础】**：系统已完成 v0.7.0 版本迭代（14 个开发阶段、7 个正式版本），形成全栈可运行容器化交付形态（数据底座 + 应用 + 监控三组 profile 一键部署），具备压测报告、性能基线、容灾演练证据与外部审查整改记录；真实 GJB 标准条目录入、私有化大模型部署等生产化事项已预留标准接口与操作手册，受授权与硬件到位节奏约束，风险可控。

## 6. 写作注意事项（诚实性护栏）

1. **口径时效**：所有数字标注快照日期（当前 v0.7.0，2026-10-08）；版本演进后以最新 tag 收官数据为准；
2. **欠账不粉饰**：技术方案定稿 §6 所列边界事项（GJB 条目 0、真实 vLLM 待部署、插件真机冒烟待联调等）必须以"待授权/待生产/进行中"表述，不得写成已完成（A-14/A-16）；
3. **术语一致**：统一使用定稿术语（A1–A5 / IR0–IR5 / 三道审阅关 / coverage / CSR）；历史文档中"两道审阅关""C1–C5""异构双轨制""符号围栏"等旧口径**不得出现在新写作中**（一代/二代术语考古需求除外，且需注明"早期方案"）；
4. **来源可指**：论文/申报书中的架构图与数据建议在草稿阶段保留出处注（本文档章节号或代码路径），定稿时按投稿/申报格式删除内部路径但保留可答辩的证据链；
5. **涉密边界**：对外材料不出现真实账号、密钥、内网地址与客户信息；demo 数据仅使用公开资料（拖曳线列阵公开文献）。
