### N-1 参考代码范例库无管理、单范例硬耦合（→ 已登记 GAP-001 P3-1）

**现状证据**：

- 范例库 = `py-engine/cad_engine/ref_code/` 目录，全部内容为一个参考脚本 `towed_array_system_twin.py`（364 行，拖曳线列阵声呐「湿端+干端」全系统数字孪生）+ 手写 `catalog.yaml` 索引（该文件的声呐类型关键词 + 13 个代码片段行号区间的手工登记）。
- 选型机制 `reference.py:53-89`：双信号关键词匹配（标题声呐类型 + 关键词重叠，top-1，阈值 0.05），**fallback = 目录里第一个 .py 文件**——无论走匹配还是 fallback，非拖曳阵需求最终拿到的范例都是拖曳阵代码，且退化是**静默的**（不报错、不降级标注）。
- 无任何管理入口：无 API、无前端页面、不接入知识库体系（kb_bases 管文档，不含代码范例）；新增一个声呐类型的范例 = 改 catalog.yaml + 往 Python 包目录塞 .py + git 提交 + **重启 worker**（`reference.py:42-48` 进程内文件缓存）。
- 范例不是「参考」而是模式注入：`agents/a3_cad/agent.py:251-268` 生成 prompt 明列「必须复制的建模模式」（柔性段 spline+sin²+sweep、空心管 cut、沿曲线放置、intersect 截取、z_cursor 顺序装配），validators 静态检查/自动修复按同一套拖曳阵范式标定。《技术方案定稿》§自述「z_cursor 顺序装配……面向拖曳线列阵范例，不代表任意声呐结构都按 Z 轴装配」。
- 无自我造血：A5 知识沉淀只回写事实/公式到 Neo4j；gate2 批准过的成功脚本落 MinIO cad-scripts 桶后无任何机制转化为新范例——范例库永远停留在 1 个。
- 设计文档定位：《总体设计方案》仅一句「按声呐类型匹配参考范例」，从未展开范例库管理形态；属设计未细化 + 实现停留在旧仓库 T1.5 迁移原样。

**风险判断**：换声呐类型（舷侧阵 / 舰壳声呐 / 声呐浮标 / 侧扫等）时存在错误领域模式注入和同范式校验风险。源码可以确认硬耦合，但劣化幅度、是否比「无范例」更差仍需控制实验，当前不作已测结论。

**改进方案**：技术候选见 §3.3 题 1；当前由主仓自研，先止血并推进阶段 15 最小可信建模闭环，再做最小管理、检索与沉淀，依赖和验收见 DEV-001 §1/§8。

## 3. 毕设任务分派建议

### 3.1 当前筛选原则（单人硬约束）

1. **一人一题**：仅一名本科生，按 §3.7 选择一个题目；不预设多人协同，不同时承诺多题交付。
2. **独立开发**：学生在独立仓库开发，不要求克隆或启动本仓全栈，不接触核心链、迁移、网关、审计及生产库。
3. **研究与展示并重**：12 周内完成明确研究问题、基线、一个核心改进、消融/误差分析及可操作前端；CLI 只能辅助，不能替代 UI。
4. **外显通用、数据有据**：公开题目不绑定本系统，格式与技术选型由本仓事实支持；如实说明实验数据领域，不冒充已验证跨领域通用性。
5. **可退出、可接入**：独立论文实验为保底，主仓接入由维护者实施，不成为毕业前置条件；有效负结果可形成论文研究结论，按导师/学校要求验收，不承诺毕业或算法必然提升。

依据：用户本轮确认；本文件 §3.6 原有独立双轨约定；`docs/自主迭代开发计划.md` §0 的自研边界。

### 3.2 双方交付与接入纪律

**学生交付（适用于 §3.7 当前菜单）**：独立构件 + 可演示 UI + 版本化纯数据契约 + 正常/失败/证据不足样例 + 自动化验证 + 实验记录 + 独立启动说明。契约至少写清输入/输出、稳定 ID、单位、错误与降级语义、schema_version；文件按数据包相对路径或资产 ID 引用，不依赖本仓 MinIO 凭据、数据库连接或内部类。JSON/文件数据包均可，不强求独立部署 REST。

**维护者接入（轨道 B）**：负责数据导出脱敏、领域配置、本仓身份/权限校验、薄适配、迁移、路由、审计、部署和回归。下列约束属于维护者，不要求学生直接改本仓：

1. API/契约先评审；IR 只增可选字段，旧快照可读；新表启动时核实下一可用 Flyway 编号，不预占已使用编号。
2. 新端点按职责评审路由；使用既有前缀也需确认鉴权、权限及审计，不能把「路由无需新增」视为零接入成本。
3. 检索/LLM 失败显式返回真实降级或错误；证据不足可拒答，不造成功、分数或概率。
4. Python 改动同步重启 API 与 worker；依赖、迁移和启动步骤写入接入说明。
5. 主仓合入按变更范围通过 Python/Java/前端及相关 e2e 验证；学生独立交付先通过数据契约验证。未选题、学生延期均不阻塞主仓。

依据：`docs/00_开发约束与协作规范.md:104`（契约）、`:112`（快照）、`:116`（诚实原则）；`docs/HANDOFF.md`「环境注意」的路由/重启纪律。即插即用表示接入边界可测试，不表示维护者无需适配。

### 3.3 技术候选池（一，当前是否派发以 §3.7 为准）

#### 题 1 · 参考代码范例库管理与检索式范例选择（含沉淀闭环）

**做什么**：N-1 缺口三层治理——管理产品化 / 检索式选范例 / 范例沉淀闭环。

**关键技术**：
- 存储：PG 新表 `ref_scripts`（编号、名称、声呐类型标签、关键词、描述、MinIO object_key、sha256、片段索引 JSONB、状态、版本）+ MinIO 新桶 `ref-scripts`——照 T13.7 元数据四表与 ADR-002 桶管理先例；
- 检索：两级——关键词（catalog.yaml 语义入库化）+ 向量（Milvus 新集合，pymilvus>=2.4 已在依赖，embedding 走 KB 管线同款供应商调用）；
- 沉淀：`ast` 模块做脚本常量剥离生成参数化模板；沙箱回归复用 `cad_engine/sandbox.py` + `geometry_inspect.py` 质量门；候选走 pending → 人工确认（复用 A5「只产 pending、绝不直写」与知识关 UI 模式）。

**技术路线与落点**：
1. **M1 管理闭环**：Flyway 建表 + MinIO 桶 + CRUD 端点挂 `/api/v1/kb/references/**`（**复用 kb 网关路由零改动**）+ 知识库页新 Tab（照 RegistryTab 惯例）+ catalog.yaml/拖曳阵脚本一次性迁移脚本；
2. **M2 检索式选型**：`cad_engine/reference.py` 的 `CodeSearchService` 内部换数据源（当前 `top_n` 仍提前返回单结果；先评审结果列表契约，由适配层兼容旧调用，不宣称新增 `top_k` 天然兼容），embedding 索引构建 + 相似度 top-k；检索不可用回关键词；无领域匹配时仅进入已验证通用/无领域范例模式，逐级标注来源（A-14）；改完**重启 worker 生效**；
3. **M3 沉淀闭环**：真实 gate2 批准记录驱动的事务后事件/可靠候选任务（`finalize_version` 只产新版 IR3，不代表批准）→ Celery 任务：脚本脱敏泛化 → 沙箱回归 + geometry_inspect 实测达标 → pending 候选 → 管理页确认入库；
4. **M4 实验报告**：「无范例 / 错域范例 / 对域范例」三档对比（生成成功率、修复循环次数、CHK-GEO-NUM 超差率），回归用例可复用协议脚手架；真实生成质量实验须另定数据、模型/提示词/范例版本和重复运行方案，不能把 7 条混合 e2e 等同质量评测集。

**自研接入与验收**：prompt 与 validators 的领域配置由维护者治理，来源追踪可能涉及 IR3 加法演进；审计加 `kb.ref.*` 规则。M1 可独立交付管理能力，但不能宣称已解决泛化性；数据、缓存、版本和生成质量验收见 DEV-001 §1。

#### 题 2 · 知识库检索增强——稀疏稠密混合与 RRF 多源融合

**做什么**：为五级降级检索增加稀疏通道与多源排序融合；重排序真实供应商实测；对比实验报告。

**关键技术**：
- 稀疏通道两路线：**路线 A（推荐起步）** `rank_bm25`（纯 Python，BSD-3）内存索引按库懒加载——复用 `GraphRAGService._ensure_corpus` 的 TTL 懒加载模式（HANDOFF 教训：跨进程内存态不可靠，必须查库刷新）；**路线 B（进阶对比）** Milvus `v2.4.17` → 2.5.x 升级启用原生 BM25 稀疏向量（compose 镜像位 `deploy/docker-compose.yml:140`，需兼容性验证）；
- 融合：RRF（reciprocal rank fusion，score = Σ 1/(k + rankᵢ)，k=60），首版融合稠密/稀疏同一文档块候选；实体层需先建立实体→块 ID 对齐，三源作为扩展；
- 重排序：T13.6 已建的 `/rerank` 配置驱动客户端接真实供应商（BGE-reranker 类）；
- 评测：命中率@k / MRR / nDCG + 延迟；查询集从 4 文档 439 chunks 构造 30–50 条带 ground truth（LLM 辅助生成 + 人工校验，构造方法如实标注，A-16）。

**技术路线与落点**：`py-engine/knowledge/service.py` 检索链内加融合层（vector 级前后）；缓存键对齐 T14.8 范围语义（unscoped/scoped 分键，`storage/cache.py`）；现有 U3.10 SearchTab 可作接口参考，独立对比/标注/批量实验 UI 仍需设计。

**移植约束与验收**：五级降级链语义与轨迹上报不变（A-14）；检索 P95 对照基线 1.3s 出差距报告；`kb_pipeline` e2e 回归绿。

#### 题 3 · 对话式需求解析（A1 前置对话层 + Chat UI）

**做什么**：一次性表单升级为多轮对话——主动追问澄清缺失项、需求渐进生成、确认后进 A1。

**关键技术**：
- 后端：py-engine 新增对话域（PG 表 `req_chat_sessions`/`req_chat_messages` + `/api/v1/reqchat/**` 端点；网关新路由一条，先例 `/api/v1/llm`；或 Java workflow 编排薄层调 py——若走 Java→py 需遵守 `HttpClient.newBuilder().version(HTTP_1_1)` 纪律，HANDOFF 已记 h2c 丢 body 坑）；
- 对话策略：系统 prompt 三态状态机（收集 → 澄清 → 确认）+ 完整性议程直接复用 IR1 `missing_items` 同款清单语义；多轮上下文窗口管理；
- 产出：确认后拼装分段编号的自然语言需求全文 + 完整性自评清单 → 走既有 `POST /sessions` 建会话（**A1 本体零改动**）；
- 前端：新建会话入口（当前为 NewSessionPage，旧 NewSessionDrawer 已被替代）加「对话模式」；聊天 UI 自组（消息列表 + 流式打字机，Agent 日志面板先例；AntD 无原生聊天组件）。

**移植约束与验收**：IR0/A1 契约零变更；对话端点入审计（`reqchat.*`）；LLM 失败如实中断不伪装；py 单测（状态机）+ vitest（组件）；e2e 可加一条 mock LLM 对话轮用例。

#### 题 4 · 审阅与交付深化——统一检查表、全参数 Diff 与冻结导出门

**做什么**：审阅页检查表七列视图、IR2 版本间全参数 diff、导出补未决项章节与全链版本清单、冻结版本导出门。

**关键技术**：
- 检查表：IR2 parameters × IR3 features（linked_param_id）× IR4 issues 三源对齐——**推荐前端三接口组装**（IrSnapshotController 读侧已有，零后端改动即得 M1）；
- 全参数 diff：前端双版本 JSON 对比（变更/新增/删除三分类 + derivation 变化高亮）；
- 未决项章节：`py-engine/docgen/export_docx.py` 模板加章（工作稿可读当前 IR1；正式批准版按冻结清单中的 IR1/上下文版本读取，不混用 latest）；
- 冻结导出门：先由主仓在批准事务记录 IR2/IR3/IR4 的确切版本组合、有效性和产物哈希，再按该组合读取和验证；当前 `review_records.ir_snapshot_id` 在 gate2 只锚定 IR3，`expectedSnapshotVersion` 可选，不是完整组合冻结。T14.5 产物哈希可复用，导出清单与导出哈希仍需实现。

**功能分解与落点**：M1 检查表/diff；M2 未决项章节（docx/pdf 共链）；M3 冻结门（批准事务 + 导出端点校验 + 按钮态）。这不是当前实施顺序：先评审批准组合契约，核心内核先于完整视图，排期见 DEV-001 §3/§8。

**移植约束与验收**：契约加法（导出清单可加版本组合字段）；批准组合记录/事件等 Java 侧改造由维护者承担；`phase2_pipeline` e2e 回归（门语义）；M1 即最小可交付。

#### 题 5 · 多 CAD 格式解析接入（DXF 先行，DWG/SLDPRT 接入论证）

**做什么**：DXF 解析入参考资产体系；DWG/SLDPRT 做接入路径论证。

**关键技术**：
- `ezdxf`（MIT，纯 Python，零系统依赖）解析 DXF：图层/块/实体统计/关键尺寸结构化提取；新依赖单独成步（显式 pip install + 冒烟，UI-1 教训）+ requirements.txt 注明许可证；
- 产出两去向：a) 转 KB 文档流（生成结构化 md 中间格式，走既有 kb 上传/分块/抽取管线参与检索）b) 转题 1 范例库的几何参考资产（与题 1 联动点）；
- DWG：LibreDWG（GPL）以**独立转换进程**接入——不引入其代码（ADR-003 拒绝 GPLv2 代码引入的先例；进程调用不构成代码衍生，论证过程如实写入论文）；SLDPRT 闭源，仅论证（SolidWorks API/商业转换服务成本对比）。

**技术路线与落点**：`kb/parsers.py` 的 `SUPPORTED_FORMATS`（现 `pdf/docx/xlsx/md/txt`）加 `dxf` + 解析分支；worker `kb_build` 任务复用；前端 DocumentsTab 上传白名单同步放行。

**移植约束与验收**：A-16——不支持格式明确报错（现白名单行为保持）；解析失败走 kb 管线既有降级；单测（ezdxf 样例文件集）+ kb_pipeline e2e。

#### 题 6 · 知识图谱治理——手动编辑、实体合并与质量分析

**做什么**：图谱编辑模式、实体/关系增删与合并去重、图谱质量指标卡。

**关键技术**：
- 后端：Neo4j Cypher 写端点挂 `/api/v1/kb/graph/**`（**复用 kb 网关路由零改动**）——节点/关系 CRUD、合并（目标节点吸收关系 + 删源，单事务）；标签与关系谓词白名单校验（对照 `storage/neo4j_store.py` 本体常量）；
- 质量指标：Cypher 聚合（孤立节点、重复候选=名称相似、连通分量）+ 前端指标卡；
- 前端：GraphTab 编辑模式（D3 事件 + 表单 + 合并向导 + 确认弹窗，可视化已有）。

**移植约束与验收**：全写操作审计（`kb.graph.*`）；与 A5 回写白名单互不干扰（独立端点）；图操作带 kb_bases 范围语义（多库过滤对齐）；操作可撤销或至少留变更记录。

### 3.4 技术候选池（二，非当前派发承诺）

#### 题 7 · 建模映射架构（当前整题自研，不列单人菜单）

**关键技术**：IR2 parameters 全量结构化注入 A3 prompt（JSON 块替代纯文本转述）；输出侧新增「参数→对象映射」结构（LLM 结构化输出 + 沙箱执行期 CadQuery 对象命名/元数据登记双通道互证）；SEG 身份（显式语义 ID 与实测互证优先；旧 STEP 几何/拓扑候选匹配允许歧义，不能以质心键保证跨版本稳定）；语义检查器三族规则（孔径=圆柱直径族 / 壁厚=同心圆柱差 / 长度=轴向范围）挂 A4。

#### 题 8 · vision-LLM 视觉校验旁路（研究验证题）

**关键技术**：先由维护者提供 GLB/固定视图包；独立转换 STEP 须包含 CadQuery/OCCT 导入与镶嵌，再接 trimesh 或渲染前端（`py-engine/convert_worker.py:59`），离屏环境需先验证；vision 客户端照 `kb/ocr.py` 先例（SiliconFlow chat + base64、temperature=0、版面标记清洗）；结构化判词 JSON（检查项/结论/置信度），**仅产 warning 级**。

**落点与约束**：A3 后旁路可选步骤（env 开关默认关，独立 Celery 任务或 hook）；A-07——不参与 error 判定、不进 CSR 分母；评测用历史错模型会话（如 `ad769c7e` 类）+ 正确模型构造盲测集；论文如实交代 ADR-003 立场（本研究即验证其重启触发条件）。

#### 题 9 · 项目与任务管理增强包（保底题）

**关键技术**：Flyway 加列 `projects.priority`/`deadline`；任务中心 = workflow 新增 TaskController（跨会话任务列表 + 状态过滤，PG 读侧）；DLQ 查看/重派 = RabbitMQ management API（15672）只读代理端点 + 重派（重新 publish，幂等闸门既有）；**预计剩余时间** = `session_logs.stage_duration` 埋点（T10.3 已有）PG 滑动窗口中位数 × 剩余阶段数——本题的算法点，救论文性；看板视图分组列表起步（dnd-kit 拖拽进阶）。

**移植约束**：RBAC 可见性（T13.4 项目成员过滤）；状态机乐观并发不动；重派走既有 RETRY 语义不另开旁路。

#### 题 10 · IR4 校验问题的 AI 修复建议（真能力版）

**关键技术**：上下文组装（issue + 参数四件套 + 溯源上下文 + 几何实测值 + KB 依据）；LLM 结构化建议（动作类型枚举：改参数值 / 回退 A2 / 回退 A3 / 补知识，附建议值与依据引用）；**幻觉控制后处理**——数字集合过滤只作弱基线；核心校验绑定对象/参数 ID、单位、证据 ID 与支持关系，证据不足拒答；公式新值不由 LLM 自行产生（详见 §3.7 E）。

**落点与约束**：只读建议端点（不写库、不触发管线，网关路由照 `/api/v1/llm` 先例新增或挂 kb 前缀评审定）；前端 IssueExplorer 加「生成建议」+「仅供参考、人工裁决」标注（A-09）；生成失败如实报错；本轮不与完整题 4 合并，防止研究、UI 和核心接入同时超量。

### 3.6 课题背景表述与独立开发双轨模式（外显通用、内核有据）

**原则**：每道题以通用研究问题对外表述，题目/开题/演示不绑定本系统；技术选型与接口有本仓依据，未有字段明确标为拟定契约。可使用公开通用样例演示、本仓脱敏数据验证；论文如实说明数据来源、领域与适用边界，不因中性命名就声称跨领域通用。即插即用以纯数据契约和可测试适配为准，不承诺移植成本趋近于零。

#### 3.7.2 A：需求澄清

- **研究问题**：同等交互预算下，缺失项驱动策略是否优于固定清单顺序与自由问答？比较完整率、矛盾率、无依据新增信息率和轮次；用预先固定量表评价，不只靠生成模型自评。
- **最小范围**：可配置维度/必填条件/追问模板、有限轮次、确认成稿、独立前端；流式输出、长期记忆、复杂账号均非必需。导师提供本仓领域配置，学生用通用工程场景；模拟用户场景与真实用户实验分别描述，不能互相冒充。
- **接口/兜底**：历史+清单配置→回复/缺失项/最终文本/状态；API 失败显式报告，可退固定清单收集，仍能完成基线比较。
- **依据**：`contracts/ir/ir1.schema.json:39` 只有缺失项字符串数组；`py-engine/agents/a1_requirement/prompts.py:7` 为领域检索维度，尚非通用评分量表；`frontend/src/pages/session/NewSessionPage.tsx:22` 为当前入口，替代旧 Drawer。

#### 3.7.3 B：可见缺陷实证

- **研究问题**：单/多视角、开放/清单提示如何影响缺陷级检出率、误报率及成本？首版仅研究缺件、明显错位、结构不一致等经标注确认的可见类别，不把内部壁厚/精确孔径超差纳入无依据承诺。
- **最小范围**：维护者先给固定图或 GLB；按基础模型分组划分调试/测试，同一模型多视角不可分散泄漏。缺陷真值来自构造记录/人工几何核验，IR4 不作为全类别正确真值；视图可见性也需标注。
- **接口/兜底**：模型/视图包+清单→warning 建议/证据视图 ID/未知状态；低效果可写适用边界，保留人工标注浏览和批量评测。精确 overlay 非首版必需，自评置信度不能冒充校准概率；不参与确定性 error/CSR。
- **依据**：`py-engine/convert_worker.py:59` 实际使用 CadQuery 导入/镶嵌后接 trimesh，单列 trimesh 不足以代表完整 STEP 渲染栈；本文件题 8 为旁路定位；`contracts/ir/ir4.schema.json:19` 为确定性 CSR 边界。

#### 3.7.4 C：重复检测与可逆合并

- **研究问题**：名称相似度→增加类型约束→增加邻域结构，比较候选对 Precision/Recall/F1 与错误合并率；评测集保留非重复难负例，不能以节点减少代替质量提升。
- **最小范围**：候选列表、局部图、合并预览、确认/撤销；不做全功能图编辑器。合并计划包含原始 ID、快照/前置条件、属性/关系冲突处置及变更记录；只操作独立副本，主仓审核后执行。
- **数据/兜底**：先验收真实重复对与必要属性；不足时受控注入别名/重复，真实集与注入集分开评估。GraphML 的历史节点数不代表现成标注集，导入与属性校验是开题关卡。
- **依据**：`py-engine/storage/neo4j_store.py:332` 明确回灌演练不属既有承诺；`:342`–`:351` 仅选择部分节点/关系字段，未完整携带描述、库归属与关系证据；`:353` 以 label:key 组合标识节点，转换时不得仅保留 key 导致冲突。

#### 3.7.5 D：检索实验台

- **研究问题**：BM25 / 稠密 / RRF / RRF+重排四组，研究查询类型、融合参数与重排的效果/延迟/成本权衡；不同时承担问答生成质量研究。图谱融合作为扩展，需实体→文档块 ID 对齐后再比较。
- **数据与实验**：30–50 查询仅先导集；人工标注相关性，按意图组划分调试/测试，同意图改写不跨组泄漏。冻结语料、模型、分块、配置与 qrels；报告 nDCG/Recall/MRR、逐查询差异及不确定性，调参不看正式测试集。4 文档支持限定语料结论，不直接推出跨领域泛化。

#### 3.7.6 E：证据绑定建议

- **研究问题**：无约束 / 数字集合过滤 / 对象—参数—单位—证据绑定校验三组；数字命中可能引用错部件，不能单凭数字存在判忠实。
- **最小范围**：每条声明返回证据 ID、对象/参数 ID、支持片段和校验状态；公式新值不由 LLM 产生。测声明级支持率、无依据数值率、错误对象引用率、有效建议覆盖率与拒答率，不能靠全拒答取得虚高分。人工核验语义支持，ID 存在也不等于证据支持。
- **接口/兜底**：issue+IR2/IR3/IR4/证据片段→建议/证据绑定/校验状态；不写库、不触发修复或管线。样本不足时补标注反例并与真实集分开；证据不足拒答或提供来源明确的模板建议。
