## 1. 新登记缺口（本次盘点新发现，此前无任何登记）

### N-1 参考代码范例库无管理、单范例硬耦合（→ 已登记 GAP-001 P3-1）

**现状证据**：

- 范例库 = `py-engine/cad_engine/ref_code/` 目录，全部内容为一个参考脚本 `towed_array_system_twin.py`（364 行，拖曳线列阵声呐「湿端+干端」全系统数字孪生）+ 手写 `catalog.yaml` 索引（该文件的声呐类型关键词 + 13 个代码片段行号区间的手工登记）。
- 选型机制 `reference.py:53-89`：双信号关键词匹配（标题声呐类型 + 关键词重叠，top-1，阈值 0.05），**fallback = 目录里第一个 .py 文件**——无论走匹配还是 fallback，非拖曳阵需求最终拿到的范例都是拖曳阵代码，且退化是**静默的**（不报错、不降级标注）。
- 无任何管理入口：无 API、无前端页面、不接入知识库体系（kb_bases 管文档，不含代码范例）；新增一个声呐类型的范例 = 改 catalog.yaml + 往 Python 包目录塞 .py + git 提交 + **重启 worker**（`reference.py:42-48` 进程内文件缓存）。
- 范例不是「参考」而是模式注入：`agents/a3_cad/agent.py:251-268` 生成 prompt 明列「必须复制的建模模式」（柔性段 spline+sin²+sweep、空心管 cut、沿曲线放置、intersect 截取、z_cursor 顺序装配），validators 静态检查/自动修复按同一套拖曳阵范式标定。《技术方案定稿》§自述「z_cursor 顺序装配……面向拖曳线列阵范例，不代表任意声呐结构都按 Z 轴装配」。
- 无自我造血：A5 知识沉淀只回写事实/公式到 Neo4j；gate2 批准过的成功脚本落 MinIO cad-scripts 桶后无任何机制转化为新范例——范例库永远停留在 1 个。
- 设计文档定位：《总体设计方案》仅一句「按声呐类型匹配参考范例」，从未展开范例库管理形态；属设计未细化 + 实现停留在旧仓库 T1.5 迁移原样。

**后果**：换声呐类型（舷侧阵 / 舰壳声呐 / 声呐浮标 / 侧扫等）时，A3 生成质量结构性劣化——错误领域的模式注入 + 校验器同范式标定，比「无范例」更糟，且全程无提示。

**改进方案（三层递进，可分层认领）**：

1. **范例库产品化**（工程层）：参考代码从包目录迁 PG 表 + MinIO 桶，CRUD API + 知识库页新 Tab（版本/启停/声呐类型登记/片段索引），照 T13.7 元数据四表模式；
2. **检索式选范例**（算法层）：范例描述 + 结构特征 embedding，按需求相似度 top-k 多范例注入，替换关键词匹配；与检索增强题（题 2）共享技术底座；
3. **范例沉淀闭环**（创新层）：gate2 批准脚本 → 参数脱敏泛化 → 沙箱回归 + geometry_inspect 质量门 → 生成 pending 候选范例 → 人工确认入库（复用 A5「只产 pending、绝不直写」与知识关既有模式）。

**评测环境现成**：真实 LLM e2e 7 条 + 子进程沙箱 + 几何实测闭环；实验设计「无范例 / 错域范例 / 对域范例」三档对比（生成成功率、修复循环次数、CHK-GEO-NUM 超差率）。

## 3. 毕设任务分派建议

### 3.1 筛选原则（按重要性排序）

1. **隔离性**：不碰 A1–A5 Agent / solver / 状态机 / contracts 核心链——被改坏的恢复成本极高；学生题限于新增模块、读侧展示、旁路检查器、独立解析器；
2. **规模**：一学期一人可交付，有清晰最小可验收版本；
3. **论文性**：有算法/对比实验成分可写；纯 CRUD 题答辩好过但论文难写；
4. **环境可行性**：第一周能独立起栈（「干净克隆 compose --profile app up」已经 PHASE-009 验收 + 现成用户指南）。

### 3.2 第一梯队（推荐，可直接派）

**题 1 · 参考代码范例库管理与检索式范例选择（含沉淀闭环）** 〔新增，缺口最实〕
- 做什么：N-1 三层全做或裁剪（层 1 保底 / 层 2 论文主体 / 层 3 优秀毕设分水岭）。
- 起点：`cad_engine/reference.py` + ref_code/ 现状、T13.7 四表模式、A5 pending 模式、知识库页 Tab 惯例、e2e 评测环境。
- 论文点：范例检索（RAG 同源技术）+ 范例增量沉淀机制 + 三档对比实验。
- 难度：中（层 1）/ 中高（层 2+3）。适合前后端均衡的学生；层 2 与题 2 可两人共享底座。

**题 2 · 知识库检索增强——稀疏稠密混合与 RRF 多源融合**
- 做什么：为五级降级检索增加 BM25/稀疏通道，与 Milvus 稠密向量 RRF 融合；可选交叉编码器重排序真实供应商实测（机制 T13.6 已建）；产出命中率@k / MRR / 延迟对比实验。
- 起点：`knowledge/service.py` 降级链、`POST /kb/search` + 知识检索 Tab（真实分数展示现成）、4 文档 439 chunks 语料、检索 P95 1.3s 基线。
- 论文点：RAG 检索优化热点，评测驱动，实验章节最好写。
- 难度：中；Python + 了解 embedding 即可。

**题 3 · 对话式需求解析（A1 前置对话层 + Chat UI）**
- 做什么：一次性表单升级为多轮对话——主动追问澄清缺失项（IR1 missing_items 机制现成）、需求渐进生成、确认后进 A1；落点为 A1 **上游独立对话预处理层**，不动 A1 本体。
- 起点：LLM 流式适配器、WS 推送、IR1 契约、聊天式前端范式全现成。
- 论文点：多轮澄清策略、对话状态管理、需求完整性度量；答辩演示效果最佳。
- 难度：中大，适合前后端都能干的学生（或两人分工）。

**题 4 · 审阅与交付深化——统一检查表、全参数 Diff 与冻结导出门**
- 做什么：审阅页统一检查表七列视图（设计值/实测值/单位/偏差/容差/状态/依据）；IR2 版本间全参数 diff；导出补「假设与未决项」章节（IR1 missing_items 入报告）与全链版本清单；冻结版本导出门（未过 gate2 不可正式导出，导出绑定批准时刻快照组合——《申报与论文写作指引》明文「整套冻结导出机制待后续实现」）。
- 起点：IR 快照 API 全量、export_docx 三章渲染、SNAPSHOT_STALE 乐观版本模式（T14.6）可复用。
- 论文点：面向可信交付的审阅信息架构（工程为主）；挂创新点 1/2。
- 难度：中，前端为主 + docx 模板；隔离性最好（纯读侧+导出侧）。

**题 5 · 多 CAD 格式解析接入（DXF 先行，DWG/SLDPRT 接入论证）**
- 做什么：ezdxf 解析 DXF → 几何/图层/块参数提取 → 中间表示 → 入知识库作参考资产；DWG 走 LibreDWG/ODA 转换路径、SLDPRT 闭源只做论证。GAP-001 唯一 ❌ 项，设计本就定位「论证阶段」。
- 论文点：CAD 中间格式解析与转换，经典毕设形态、闭环完整。
- 难度：中；隔离性极好（独立子包/独立 worker 任务）。

**题 6 · 知识图谱治理——手动编辑、实体合并与质量分析**
- 做什么：图谱页编辑模式（增删实体/关系、同名合并去重、谓词约束校验）+ 审计留痕（中间件现成）+ 质量指标（孤立节点率/重复度/连通分量）。
- 起点：D3 力导向可视化、Neo4j 直操、A5 回写白名单防误写。
- 论文点：图谱治理与实体消歧（中）；演示直观。
- 难度：中低，适合基础一般的学生。

### 3.3 第二梯队（可行，各有短板，按学生情况选）

### 3.5 落地配套建议

1. **第一周任务=环境复现而非写代码**：干净克隆 → `compose --profile app up` → 按[用户指南](ops/用户指南.md)走查 → 跑通对应模块测试；起不出的学生此时即暴露。
2. **任务书素材现成**：各题「差距/方案/验收」在 GAP-001、外部审查核验报告 §2-3、PHASE-014 §7、本文 §1 均有原文；17 条回归案例可作中期/终期检查点。
3. **简化纪律**（自宪法 CONST-001 裁剪）：每人 feature 分支不动 main；小步提交；contracts/ 非任务需要不碰；**A-16 诚实原则必须保留**（不造假数据/假按钮——答辩时是加分项）。
4. **与论文挂钩**：让学生把毕设章节挂在[申报与论文写作指引](reference/申报与论文写作指引.md)六创新点延伸上——题 1/2 延伸检索体系、题 4/10 延伸校验状态学（创新点 2）、题 7/8 延伸几何真实化（创新点 3）、题 3 延伸人在回路管线（创新点 1）。
5. **多人分工**：题 3、题 4 天然两人前后端分工；题 1 层 1 与层 2 可拆两人。
