## 1. 新登记缺口（本次盘点新发现，此前无任何登记）

### N-1 参考代码范例库无管理、单范例硬耦合（→ 已登记 GAP-001 P3-1）

**现状证据**：

- 范例库 = `py-engine/cad_engine/ref_code/` 目录，全部内容为一个参考脚本 `towed_array_system_twin.py`（364 行，拖曳线列阵声呐「湿端+干端」全系统数字孪生）+ 手写 `catalog.yaml` 索引（该文件的声呐类型关键词 + 13 个代码片段行号区间的手工登记）。
- 选型机制 `reference.py:53-89`：双信号关键词匹配（标题声呐类型 + 关键词重叠，top-1，阈值 0.05），**fallback = 目录里第一个 .py 文件**——无论走匹配还是 fallback，非拖曳阵需求最终拿到的范例都是拖曳阵代码，且退化是**静默的**（不报错、不降级标注）。
- 无任何管理入口：无 API、无前端页面、不接入知识库体系（kb_bases 管文档，不含代码范例）；新增一个声呐类型的范例 = 改 catalog.yaml + 往 Python 包目录塞 .py + git 提交 + **重启 worker**（`reference.py:42-48` 进程内文件缓存）。
- 范例不是「参考」而是模式注入：`agents/a3_cad/agent.py:251-268` 生成 prompt 明列「必须复制的建模模式」（柔性段 spline+sin²+sweep、空心管 cut、沿曲线放置、intersect 截取、z_cursor 顺序装配），validators 静态检查/自动修复按同一套拖曳阵范式标定。《技术方案定稿》§自述「z_cursor 顺序装配……面向拖曳线列阵范例，不代表任意声呐结构都按 Z 轴装配」。
- 无自我造血：A5 知识沉淀只回写事实/公式到 Neo4j；gate2 批准过的成功脚本落 MinIO cad-scripts 桶后无任何机制转化为新范例——范例库永远停留在 1 个。
- 设计文档定位：《总体设计方案》仅一句「按声呐类型匹配参考范例」，从未展开范例库管理形态；属设计未细化 + 实现停留在旧仓库 T1.5 迁移原样。

**后果**：换声呐类型（舷侧阵 / 舰壳声呐 / 声呐浮标 / 侧扫等）时，A3 生成质量结构性劣化——错误领域的模式注入 + 校验器同范式标定，比「无范例」更糟，且全程无提示。

**改进方案（三层递进，可分层认领）**：见 §3.3 题 1 技术路线展开。

## 3. 毕设任务分派建议

### 3.1 筛选原则（按重要性排序）

1. **隔离性**：不碰 A1–A5 Agent / solver / 状态机 / contracts 核心链——被改坏的恢复成本极高；学生题限于新增模块、读侧展示、旁路检查器、独立解析器；
2. **规模**：一学期一人可交付，有清晰最小可验收版本；
3. **论文性**：有算法/对比实验成分可写；纯 CRUD 题答辩好过但论文难写；
4. **环境可行性**：第一周能独立起栈（「干净克隆 compose --profile app up」已经 PHASE-009 验收 + 现成用户指南）。

### 3.2 移植性总约定（所有题共通，向学生宣贯）

产出能否「直接移植回本仓」取决于以下纪律，违反任何一条即不合入：

1. **API/契约先行**：动工先提交三样草案评审——接口契约（端点/请求响应）、表结构（Flyway 迁移）、契约文件变更（仅当任务需要动 `contracts/ir/`）——通过后再写实现；
2. **加法演进**：IR 契约只增可选字段不改既有语义（A-12 旧快照必须可读）；新表走 `java-platform/biz/.../db/migration/` Flyway 编号续排（当前已应用至 V19，V20 曾预留未落，取下一可用号）；
3. **网关路由纪律**：py-engine 新端点若不在既有前缀（`/api/v1/kb/**`、`/api/v1/llm/**`、`/api/v1/healthz`、workflow/auth/biz/notify 各自前缀）内，必须同步 `gateway/application.yml` 路由并重建 jar（宿主模式 `mvn clean package`，过期 jar 陷阱见 HANDOFF）；**能挂既有前缀的优先挂**（如题 1/6 挂 `/api/v1/kb/` 子路径 = 网关零改动）；
4. **审计规则同步**：新增写操作端点同步 `py-engine/api/audit.py` 的 `_RULES` 规则表（T13.1 模式；先例：`/knowledge/writeback` 漏登教训）；
5. **降级语义**：检索/LLM/外部解析类功能一律 A-14 如实降级——失败显性标注，不静默、不假装成功；
6. **重启与依赖纪律**：py-engine 改动须同时重启 uvicorn 与 celery worker；新 Python 依赖单独提交 + 显式 `python -m pip install` 验证 + requirements.txt 注明许可证（UI-1 echarts 教训）；
7. **合入门槛**：py 单测 + vitest（若动前端）+ 相关 e2e 全绿；学生分支 → 维护者评审合 main；产出 = 代码 + 测试 + 部署说明（依赖/迁移/路由三件套）缺一不可。

### 3.3 第一梯队（推荐，可直接派）

#### 题 1 · 参考代码范例库管理与检索式范例选择（含沉淀闭环）

**做什么**：N-1 缺口三层治理——管理产品化 / 检索式选范例 / 范例沉淀闭环。

**关键技术**：
- 存储：PG 新表 `ref_scripts`（编号、名称、声呐类型标签、关键词、描述、MinIO object_key、sha256、片段索引 JSONB、状态、版本）+ MinIO 新桶 `ref-scripts`——照 T13.7 元数据四表与 ADR-002 桶管理先例；
- 检索：两级——关键词（catalog.yaml 语义入库化）+ 向量（Milvus 新集合，pymilvus>=2.4 已在依赖，embedding 走 KB 管线同款供应商调用）；
- 沉淀：`ast` 模块做脚本常量剥离生成参数化模板；沙箱回归复用 `cad_engine/sandbox.py` + `geometry_inspect.py` 质量门；候选走 pending → 人工确认（复用 A5「只产 pending、绝不直写」与知识关 UI 模式）。

**技术路线与落点**：
1. **M1 管理闭环**：Flyway 建表 + MinIO 桶 + CRUD 端点挂 `/api/v1/kb/references/**`（**复用 kb 网关路由零改动**）+ 知识库页新 Tab（照 RegistryTab 惯例）+ catalog.yaml/拖曳阵脚本一次性迁移脚本；
2. **M2 检索式选型**：`cad_engine/reference.py` 的 `CodeSearchService` 内部换数据源（对外接口 `select_reference` 签名不变，新增 `top_k` 支持多范例注入），embedding 索引构建 + 相似度 top-k；检索不可用退回关键词再退默认，逐级如实标注来源（A-14）；改完**重启 worker 生效**；
3. **M3 沉淀闭环**：gate2 批准钩子（挂 `cad_agent/service.py` finalize 单点或 ReviewService 事后事件）→ Celery 任务：脚本脱敏泛化 → 沙箱回归 + geometry_inspect 实测达标 → pending 候选 → 管理页确认入库；
4. **M4 实验报告**：「无范例 / 错域范例 / 对域范例」三档对比（生成成功率、修复循环次数、CHK-GEO-NUM 超差率），e2e 环境 7 条真实 LLM 用例直接复用。

**移植约束与验收**：不动 a3 agent prompt 结构与 validators；IR 契约零变更；审计加 `kb.ref.*` 规则；towed array e2e 回归绿 + 新增双范例检索用例；M1 即为最小可交付版本。

#### 题 2 · 知识库检索增强——稀疏稠密混合与 RRF 多源融合

**做什么**：为五级降级检索增加稀疏通道与多源排序融合；重排序真实供应商实测；对比实验报告。

**关键技术**：
- 稀疏通道两路线：**路线 A（推荐起步）** `rank_bm25`（纯 Python，BSD-3）内存索引按库懒加载——复用 `GraphRAGService._ensure_corpus` 的 TTL 懒加载模式（HANDOFF 教训：跨进程内存态不可靠，必须查库刷新）；**路线 B（进阶对比）** Milvus `v2.4.17` → 2.5.x 升级启用原生 BM25 稀疏向量（compose 镜像位 `deploy/docker-compose.yml:140`，需兼容性验证）；
- 融合：RRF（reciprocal rank fusion，score = Σ 1/(k + rankᵢ)，k=60），融合稠密（Milvus）/稀疏（BM25）/实体层（Neo4j）三源排序；
- 重排序：T13.6 已建的 `/rerank` 配置驱动客户端接真实供应商（BGE-reranker 类）；
- 评测：命中率@k / MRR / nDCG + 延迟；查询集从 4 文档 439 chunks 构造 30–50 条带 ground truth（LLM 辅助生成 + 人工校验，构造方法如实标注，A-16）。

**技术路线与落点**：`py-engine/knowledge/service.py` 检索链内加融合层（vector 级前后）；缓存键对齐 T14.8 范围语义（unscoped/scoped 分键，`storage/cache.py`）；评测界面直接用 U3.10 的知识检索 Tab（真实分数展示现成）。

**移植约束与验收**：五级降级链语义与轨迹上报不变（A-14）；检索 P95 对照基线 1.3s 出差距报告；`kb_pipeline` e2e 回归绿。

#### 题 4 · 审阅与交付深化——统一检查表、全参数 Diff 与冻结导出门

**做什么**：审阅页检查表七列视图、IR2 版本间全参数 diff、导出补未决项章节与全链版本清单、冻结版本导出门。

**关键技术**：
- 检查表：IR2 parameters × IR3 features（linked_param_id）× IR4 issues 三源对齐——**推荐前端三接口组装**（IrSnapshotController 读侧已有，零后端改动即得 M1）；
- 全参数 diff：前端双版本 JSON 对比（变更/新增/删除三分类 + derivation 变化高亮）；
- 未决项章节：`py-engine/docgen/export_docx.py` 模板加章（数据源 = IR1 latest `missing_items`，快照读取既有）；
- 冻结导出门：规则 = IR2/IR3/IR4 当前 latest 快照 ∈ gate2 批准时刻版本组合（`review_records.ir_snapshot_id` 已冻结版本锚点）；请求带 `expectedSnapshotVersion`（复用 T14.6 SNAPSHOT_STALE 409 模式）；导出物封面带全链版本清单 + sha256（T14.5 哈希既有）。

**技术路线与落点**：M1 检查表 + diff（纯前端）→ M2 未决项章节（docx/pdf 双链同步，export_pdf 走 gotenberg）→ M3 冻结门（py 导出端点校验 + 前端按钮态）。

**移植约束与验收**：契约加法（导出清单可加版本组合字段）；Java 侧仅读不动；`phase2_pipeline` e2e 回归（门语义）；M1 即最小可交付。

#### 题 5 · 多 CAD 格式解析接入（DXF 先行，DWG/SLDPRT 接入论证）

**做什么**：DXF 解析入参考资产体系；DWG/SLDPRT 做接入路径论证。

**关键技术**：
- `ezdxf`（MIT，纯 Python，零系统依赖）解析 DXF：图层/块/实体统计/关键尺寸结构化提取；新依赖单独成步（显式 pip install + 冒烟，UI-1 教训）+ requirements.txt 注明许可证；
- 产出两去向：a) 转 KB 文档流（生成结构化 md 中间格式，走既有 kb 上传/分块/抽取管线参与检索）b) 转题 1 范例库的几何参考资产（与题 1 联动点）；

**技术路线与落点**：`kb/parsers.py` 的 `SUPPORTED_FORMATS`（现 `pdf/docx/xlsx/md/txt`）加 `dxf` + 解析分支；worker `kb_build` 任务复用；前端 DocumentsTab 上传白名单同步放行。

#### 题 6 · 知识图谱治理——手动编辑、实体合并与质量分析

**做什么**：图谱编辑模式、实体/关系增删与合并去重、图谱质量指标卡。

**关键技术**：
- 后端：Neo4j Cypher 写端点挂 `/api/v1/kb/graph/**`（**复用 kb 网关路由零改动**）——节点/关系 CRUD、合并（目标节点吸收关系 + 删源，单事务）；标签与关系谓词白名单校验（对照 `storage/neo4j_store.py` 本体常量）；
- 质量指标：Cypher 聚合（孤立节点、重复候选=名称相似、连通分量）+ 前端指标卡；
- 前端：GraphTab 编辑模式（D3 事件 + 表单 + 合并向导 + 确认弹窗，可视化已有）。

**移植约束与验收**：全写操作审计（`kb.graph.*`）；与 A5 回写白名单互不干扰（独立端点）；图操作带 kb_bases 范围语义（多库过滤对齐）；操作可撤销或至少留变更记录。

### 3.4 第二梯队（可行，各有短板，按学生情况选）

#### 题 7 · 建模映射架构（阶段 15 主菜，限最强学生 + 导师架构把关）

**关键技术**：IR2 parameters 全量结构化注入 A3 prompt（JSON 块替代纯文本转述）；输出侧新增「参数→对象映射」结构（LLM 结构化输出 + 沙箱执行期 CadQuery 对象命名/元数据登记双通道互证）；SEG 稳定标识（`geometry_inspect.py` 分段锚定从最长轴排序改为拓扑/质心聚类稳定键，跨版本对位）；语义检查器三族规则（孔径=圆柱直径族 / 壁厚=同心圆柱差 / 长度=轴向范围）挂 A4。

**落点**：`agents/a3_cad/`（prompt + 输出契约）、`cad_engine/geometry_inspect.py`、`agents/a4_validation/agent.py`。**移植约束**：IR3 契约加法（mapping 可空，旧快照兼容）；可拆四个子题独立认领（参数注入 / 映射契约 / SEG 标识 / 语义检查器）；验收 = 回归案例 02/03/04 + towed/cad_tune e2e 全绿。

#### 题 8 · vision-LLM 视觉校验旁路（研究验证题）

**关键技术**：多视角渲染用 `trimesh`（>=4.0 已在依赖，离屏三视图 + 轴测）；vision 客户端照 `kb/ocr.py` 先例（SiliconFlow chat + base64、temperature=0、版面标记清洗）；结构化判词 JSON（检查项/结论/置信度），**仅产 warning 级**。

**落点与约束**：A3 后旁路可选步骤（env 开关默认关，独立 Celery 任务或 hook）；A-07——不参与 error 判定、不进 CSR 分母；评测用历史错模型会话（如 `ad769c7e` 类）+ 正确模型构造盲测集；论文如实交代 ADR-003 立场（本研究即验证其重启触发条件）。

#### 题 9 · 项目与任务管理增强包（保底题）

**关键技术**：Flyway 加列 `projects.priority`/`deadline`；任务中心 = workflow 新增 TaskController（跨会话任务列表 + 状态过滤，PG 读侧）；DLQ 查看/重派 = RabbitMQ management API（15672）只读代理端点 + 重派（重新 publish，幂等闸门既有）；**预计剩余时间** = `session_logs.stage_duration` 埋点（T10.3 已有）PG 滑动窗口中位数 × 剩余阶段数——本题的算法点，救论文性；看板视图分组列表起步（dnd-kit 拖拽进阶）。

**移植约束**：RBAC 可见性（T13.4 项目成员过滤）；状态机乐观并发不动；重派走既有 RETRY 语义不另开旁路。

#### 题 10 · IR4 校验问题的 AI 修复建议（真能力版）

**关键技术**：上下文组装（issue + 参数四件套 + 溯源上下文 + 几何实测值 + KB 依据）；LLM 结构化建议（动作类型枚举：改参数值 / 回退 A2 / 回退 A3 / 补知识，附建议值与依据引用）；**幻觉控制后处理**——建议数值必须属于输入上下文数值集合，否则弃置该项并如实说明。

**落点与约束**：只读建议端点（不写库、不触发管线，网关路由照 `/api/v1/llm` 先例新增或挂 kb 前缀评审定）；前端 IssueExplorer 加「生成建议」+「仅供参考、人工裁决」标注（A-09）；生成失败如实报错；可与题 4 合并为一个学生的完整题。

### 3.6 课题背景表述与独立开发双轨模式（外显通用、内核有据）

**原则**：每道题对外呈现为一个**通用研究/工程问题**——论文题目、开题背景、摘要与公开演示中不出现本系统名称与领域细节；但技术选型、数据格式、接口契约、评测口径**全部取自本仓既有事实**（见下方术语对齐表），学生的独立原型与本仓实现同构——产出「换壳即用」，移植成本趋近于零。

- **外显层（给学生/答辩/论文看的）**：通用问题 + 中性命名的数据集 + 自选轻量栈；看不出与某个具体系统的绑定；
- **内核层（实际依据）**：数据包从本仓真实导出、JSON 结构即本仓契约、算法挂点即本仓模块、评测指标即本仓基线（检索 P95、e2e 用例、17 条回归案例）。

**双轨交付**：

| 轨道 | 定位 | 要求 |
|---|---|---|
| A · 独立原型（保底，论文主体） | 通用问题 + 导出数据包 + 自选轻量栈 | 不要求跑通本仓；数据格式与本仓契约对齐（见下数据包），论文实验可复现 |
| B · 移植回仓（加分，工程落地） | 按 §3.2 移植性约定 | 环境复现通过后 feature 分支开发，维护者评审合入 |

**即插即用交付形态与插件接口**（耦合控制的核心约定）：学生交付**独立构件**（Python 包 / 独立 REST 服务 / 前端组件集），接口为纯数据进出（JSON 输入→JSON 输出），**不要求也不允许直接在本仓代码树上开发**（轨道 A）；本仓侧合入 = 维护者按既有挂点写薄适配层。任何一题掉队或延期都不伤主仓。
