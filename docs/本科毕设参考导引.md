# 本科毕设参考导引（面向「知识增强对话智能体」课题）

> 你的课题：**面向设计文档生成的知识增强对话智能体设计与实现**，研究重点＝**知识检索与对话的协同方式** + **多轮交互中的上下文管理**。任务书见 [`本科毕业设计任务说明_知识增强对话智能体.md`](本科毕业设计任务说明_知识增强对话智能体.md)。

## 这个仓库与你的课题是什么关系

本仓库是一个**已投入运行的声呐装备辅助设计系统**（需求解析→方案生成→CAD 出图→校验→知识沉淀五步管线）。它**不是你的开发基座**——你在自己的仓库里基于 Pi Agent + GraphRAG 独立开发；本仓库的作用是：当你思考"检索什么时候触发、对话上下文怎么组织、检索证据怎么变成带出处的结论"这类设计问题时，这里有**真实工程环境下的参考实现**可以对照。

## 参考阅读地图（按你的两个研究重点组织）

### 重点一 · 知识检索与对话的协同

| 位置 | 看什么 |
|---|---|
| `py-engine/knowledge/service.py` | 三级降级检索：Neo4j 实体层 → Milvus 向量 → 文本关键词；每级命中/降级轨迹如实上报——「检索不到时怎么办」的一种工程答案 |
| `py-engine/agents/a1_requirement/agent.py` | 需求文本 → LLM 子查询规划 → 并行检索 → 结构化结果（含缺失项清单）——「何时检索、检索什么」的一种工程答案 |
| `py-engine/api/kb.py` 的 `/kb/search` 端点 + `frontend/src/pages/kb/SearchTab.tsx` | 检索演示界面：命中分数、来源文档、命中层级、降级轨迹如何呈现给用户 |
| `py-engine/agents/a2_scheme/` | 检索证据 → 带出处结论的转换：参数按来源四分类（公式/案例/军标/估算），每个值带溯源引用——「证据如何变成依据」的契约化做法 |
| `py-engine/kb/` | 知识库构建管线：多格式文档解析→分块→结构化抽取→图谱与向量索引（GraphRAG 落地的完整前序工程） |

### 重点二 · 多轮交互中的上下文管理

| 位置 | 看什么 |
|---|---|
| `py-engine/cad_agent/` | 本仓最贴近你课题的模块：服务端多轮对话 Agent（ReAct 文本协议、逐轮上下文组织、Token 预算、工具调用状态机、每轮产物留痕与版本化） |
| `contracts/ir/` | 中间表示 JSON Schema：已确认需求 / 待确认信息（IR1 `missing_items`）/ 知识建议如何**分态契约化**，多轮修改如何用不可变版本快照管理（旧态可回溯） |
| `docs/adr/ADR-004-CAD交互微调集成路线.md` + `docs/phase/phase-8-CAD交互微调-FreeCAD集成.md` | 多轮对话式设计微调的完整架构决策与设计文档——含上下文、版本、人工确认关的取舍论证 |

### 建议阅读顺序

1. 任务书 → 2. `knowledge/service.py`（检索骨架）→ 3. `a1_requirement/agent.py`（检索-需求协同）→ 4. `cad_agent/`（多轮 Agent）→ 5. `contracts/ir/`（上下文分态契约）。总代码量不大，每个文件头部都有模块说明。
