## 1. 背景

1. **无数值级几何校验物**。A3 的成功判据是「沙箱无 traceback + 产出 STEP」（`a3_cad/agent.py` run Step 3）；IR3 的 features 由 `_build_ir3` 按 IR2 参数 id **批量生成占位镜像**（`segment` 恒为 `"model"`、`geometry` 仅一句 note），并非从模型提取。A4 的「几何自洽」（CHK-GEO-DUP-FEATURE / CHK-GEO-LINK / CHK-GEO-STEP / CHK-GEO-SCRIPT）因此只做引用完整性，且 **CHK-GEO-LINK 恒真**——「能编译但几何画错」的 silent geometric error 目前无任何确定性校验可拦截。
2. **mockup 欠账**。已确认基线 mockup 06 明确承诺数值级复核画面（「P-002 阵列孔径 23.5 m 复算 (48−1)×0.5，但特征包络 24 000 mm，偏差 2.1% 超容差」）；现实现与之不符。
3. **外部调研输入**。CADDesigner（浙大，GPLv2）以「执行反馈 + 视觉反馈双闭环」为核心贡献；其代码不可引入（GPLv2 强 Copyleft，且本项目目标形态含交付部署=分发；核心依赖 CadQuery 为 Apache-2.0，与 GPLv2 单向不兼容）。方法可自由借鉴。

## 2. 决策

1. **采纳「方案 B」并定为阶段 7（PHASE-007）**：IR3 features 真实化（从 STEP 网格提取整体/分段几何摘要）+ A4 数值级几何复核（linked 参数 vs 实测维度，容差可配，确定性、无 LLM）。方案详见 PHASE-007。
2. **否决「方案 A」（A3 内 vision-LLM 视觉反馈闭环）的当期实施**，降级为留观项，**重启触发条件**（满足其一再立项）：
   - 实测出现「度量校验全过、但人工审阅发现几何错误」的案例 ≥ 2 例；
   - 系统转向无人值守批量生成/交付形态（无人工 gate2 兜底）；
   - 领域扩展到视觉可辨几何丰富的对象（当前拖曳阵为细长回转体，三视图信息量低，vision 通道性价比差）。
3. **不引入**：CADDesigner-Code 任何代码（GPLv2）；SketchPad（GraphRAG 已覆盖且更强）；其需求扩展子 agent（A1 已覆盖）；SimpleCADAPI 迁移（**已核实为 Apache-2.0**，法律干净，但与 CadQuery 双 API 面并存成本高——列为中期备选，引入前须另立 ADR）。
4. **顺手修复**：`trimesh` 未在 `py-engine/requirements.txt` 声明（convert_worker 实际依赖，新环境转换链路断裂）——随阶段 7 T7.0 补记。
5. ECIP（显式上下文 imperative 范式）仅作为 A3 生成脚本的组织风格建议吸收进 prompt，不构成架构改动，不单独立项。

## 3. 理由

- 本系统是**人在回路**架构（A-11 双审阅关 + 三维预览人工确认），CADDesigner 的视觉闭环补的是「无人工兜底」的洞，我们的兜底是 gate2 的人；自动化应优先用于**强化人工裁决材料**（确定性数值复核），而非用 vision-LLM 替代人。
- A-07：数值判断交给代码不交给 LLM；度量校验零 token、确定性、可单测——与架构同构。
- 数值校验直接消偿 mockup 06 欠账，属「实现回归已确认基线」；vision 闭环则属新增能力，当前无实证发生率支撑其成本（新依赖、子进程、非确定性判词、A-13 循环语义复杂化）。

## 4. 后果

- 正面：IR3 features 从占位变真实（A-16）；A4 获得数值级几何复核能力；审阅关② 的裁决材料包含实测偏差；整体包围盒校验可拦截「全长/孔径级」错误。
- 代价：`contracts/ir/ir3.schema.json` 加法演进（`geometry` 内部结构定义 + 新增可选 `geometry_summary` + `linked_param_id` 放宽可空），需契约测试同步与全链路回归（towed array e2e）；A3 增加 STEP 提取子进程步骤（复用 convert_worker 的子进程隔离模式，含失败降级路径）。
- 兼容性：旧快照不可变（A-12）不受影响；A4 数值支路以「features 携带实测 bbox」为启用开关，旧数据自动跳过并如实提示。
- 风险与回滚见 PHASE-007 §7。
