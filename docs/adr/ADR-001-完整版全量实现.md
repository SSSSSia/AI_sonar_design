# ADR-001：v2 采用完整版五层架构全量实现，取消 demo 级裁剪

| 项 | 内容 |
|---|---|
| ADR 编号 | ADR-001 |
| 状态 | 已接受 |
| 日期 | 2026-09-16 |
| 关联 | CONST-001 v1.0 → v1.1（§2 全部重写） |

## 背景

宪法文档 v1.0 为控制初期成本，给出了 demo 级裁剪决策（单 Python FastAPI 后端、SQLite、Chroma、本地文件存储、进程内任务队列、简化认证等，即原 D-01~D-12）。用户评审后明确决策：**"什么都要完整版的"** —— 按 P3《智能辅助声呐装备设计系统_总体设计方案》的完整五层架构全量实现，不做裁剪。

## 决策

1. **后端**：Java 17 + Spring Boot 3 平台层（网关/鉴权/业务管理/编排状态机）+ Python 3.12 + FastAPI 算力层（A1–A5/CAD/求解/检索），双后端按 P3 §4.8 协作（同步 REST + 异步消息队列）。
2. **数据底座**：PostgreSQL 17 + Neo4j 5 + Milvus + MinIO + Redis 7.2 + RabbitMQ，docker-compose 容器化一键起。
3. **网关与安全**：Nginx + Spring Cloud Gateway；Spring Security + JWT + RBAC 完整实现。
4. **IR 契约**：根目录 `contracts/`（JSON Schema 单一事实源），Java/Python 两侧生成或校验对齐。
5. **LLM**：统一适配器，目标形态私有化 vLLM + Qwen/DeepSeek；开发期以公网 OpenAI 兼容 API 作为 fallback（P3 §4.7 允许），配置可热切换、禁止硬编码供应商。
6. **暂缓项**仅限设计文档明确标注的远期/后续扩展（多声呐类型泛化、修复策略自学习、多方案比选、3D 点击反向定位、多租户、实际军网/昇腾部署）；提前动工需补设计文档 + ADR。

## 风险对冲（2026-09-16 补充修订）

原风险对冲提出"先跑通纵向切片，再横向铺开"。经用户指出：**纵向切片（需求→检索→方案→CadQuery→STEP）在旧仓库 `../Sonar_cad_design` 中已端到端实现**（agent/ 三阶段固定管线 + graphrag_service 知识库 + Ref_code 范例），v2 无需重建，改为**迁移适配**：

### 旧骨架与完整版架构的差距（2026-09-16 代码走查后修订）

实际走查 `agent/`（约 1400 行）与 `graphrag_service/`（约 650 行）后确认：旧骨架是**同步、进程内、字符串传递的单机 workflow**，与完整版架构的差距是结构性的，**骨架本身不可直接迁移**：

| 维度 | 旧骨架现状 | 完整版要求 | 差距定性 |
|---|---|---|---|
| 数据流 | Stage 间传裸字符串（`design_document: str` / `generated_script: str`） | IR0–IR5 契约（Pydantic/JSON Schema，参数带 source_type/trace_id） | **重写** |
| 能力覆盖 | 仅 C1–C3 雏形（且 A1/A2 混在一个 LLM 调用） | A1–A5 + 两道审阅关 + 溯源 | **新增** A4/A5/审阅关 |
| 执行模型 | 同步一次跑完，print 输出 | 异步任务（MQ/Celery）+ 断点恢复 + WebSocket 推送 | **重写** |
| 编排 | 130 行进程内 for 循环 | Java 状态机（审阅关暂停/裁决/局部回环/IR 版本） | **重写** |
| 持久化 | 文件落盘 output/ | PG/MinIO/IR 快照 | **新增** |
| 校验 | 仅"代码跑不跑" | A4 约束/公式/军标校验引擎 | **新增** |

### 旧代码 → v2 迁移映射（按复用等级标注）

| 旧模块 | v2 去向 | 复用等级 | 说明 |
|---|---|---|---|
| `prompts.py`（227 行模板） | 提示词模板管理（5.16） | ★ 资产直接入库 | 整合/生成/修复/系统提示词直接搬 |
| `graphrag_service/sdk.py + service.py` | `py-engine/knowledge/` | ★ 直接迁移 | 封装成熟（降级策略/日志抑制），仅需异步包装 |

**量化估计**：原样可用资产约 900 行代码 + KB 索引 + 范例（占旧库约 40%）；管线外壳、A4/A5、审阅关、持久化、API 层全部新写。

### 结论

- roadmap 阶段一 = **新架构骨架 + 资产迁移**：先搭 contracts/Java 状态机/任务队列/数据底座骨架，再按上表迁移内脏，A1–A3 在新契约下重新组装出首个闭环；A4/A5 与审阅关为紧随其后的增量。
- 旧仓库保持只读参照，不再迭代；其 `.env`、KB 数据可复制复用，密钥不入库。
- 旧骨架的真正价值是**方法链路已验证**（固定管线优于 ReAct、三阶段闭环、修复循环收敛），这些设计决策直接继承，避免 v2 走弯路。
