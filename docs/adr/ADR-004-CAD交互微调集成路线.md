## 1. 背景

1. **新需求**（导师要求）：设计人员可在 CAD 软件中点击/操作平台生成的三维模型，并用自然语言对话微调。现有系统 A3 为「生成即定型」：LLM 生成 CadQuery 脚本 → 子进程沙箱 → STEP 进 MinIO，前端仅只读预览，模型定型后无任何交互修改通道。
2. **既有资产**：用户自研 FreeCAD 插件 CadAgent（`D:\Download\FreeCAD\Mod\CadAgent`，只读参考）已实现「软件内对话生成 CAD」，其 AgentLoop 纯状态机、CQ→Part 翻译层、质量门禁可复用；但会话与 3D 文档脱节、快照关闭即删、无版本概念、LLM key 明文存插件 `.env`——单机自治架构的固有缺陷。
3. **业界事实**（2026-09 调研，详见 PHASE-008 §2）：传统 CAD 厂商原生 AI 助手多为文档问答；外部 Agent 接 CAD 的事实标准是「CAD 内薄插件 + RPC + 后端大脑」（freecad-mcp 2455★ 等）；对话微调路线中参数化编辑可靠性最高（LLM4CAD-Editor 96.3%）但需特征树基建，「脚本增量编辑」为务实起步路线。

## 2. 决策

1. **目标 CAD = FreeCAD（≥1.0）**：唯一同时满足「Python API 全开放 + headless + 可嵌面板 + 零许可门槛」的候选；商用 CAD（SOLIDWORKS/NX/CATIA/Creo）全部要求本机授权与 COM/专有运行时，列为后续适配层（文件级 STEP 互通先行）。
2. **大脑后置平台**：LLM 循环（AgentLoop 改造迁移）、质量门禁、会话状态、模型版本全部在 py-engine/PG/MinIO；FreeCAD 插件瘦身为「登录（平台 JWT）+ 拉模型 + 聊天面板 + 工具执行器」。**插件零凭据**（根治 CadAgent `.env` 明文 LLM key 问题）。
3. **微调机制（一期）= 增量编辑脚本**：每轮 LLM 生成一段自包含编辑代码（输入=当前模型，输出=新模型），经平台下发插件、在 FreeCAD 主线程执行（执行前 FCStd 快照 + 语法预检）；收敛后插件导出 STEP+FCStd 上传，服务端 `geometry_inspect` 实测并**追加 IR3 新版本**（复用 `ir_snapshots` 不可变版本链，GLB 预览按版本自动失效）。**已知局限如实标注**：STEP 导入丢参数历史、编辑脚本非特征树参数化操作——二期演进方向（见 §4）。
4. **管线位置 = A3 之后、审阅关②之前**：审阅的就是微调定稿的最新 IR3 版本；`ReviewRecord.ir_snapshot_id` 天然冻结批准版本；微调会话活跃时 gate2 前端提示先定稿，防止审阅期间版本漂移。
5. **通信 = 插件发起的 HTTPS 长轮询**（工具调用下发/结果回收/对话流），不依赖插件侧入站连接（ NAT/防火墙友好）；事件推送复用 notify 8084（新消息类型 `cad_tune_updated`，契约加法演进）。
6. **代码落位**：插件代码迁入本仓库 `clients/freecad-plugin/`（原 CadAgent 仓库只读参考）——协议代码可单测、与平台同版本演进；CadAgent 的 `agent/cq.py`/`core/quality.py`/`ui/*` 等按 PHASE-008 §2.2 三栏清单复用/改造/废弃。
7. **否决项**：
   - **插件自治**（CadAgent 现状延续，平台只做文件收发）：LLM 配置两套、微调过程溯源断链（违 A-02）、状态管理缺口依旧；
   - **Web 3D 工作台为主**（不装桌面 CAD，在 ModelTab 内做点选+微调）：与「和 CAD 软件集成」需求字面不符，点选/建模交互能力受限于浏览器；作为二期可选增强保留；
   - **商用 CAD 首发**：授权门槛 + COM/专有 API 工作量数倍，且无法复用既有 FreeCAD 资产；
   - **服务端 headless FreeCAD 替代插件**（服务端装 FreeCAD 跑渲染/建模）：设计人员「点击操作三维图」必须在 GUI 内，headless 只能当转换器——现有 cadquery 子进程沙箱已覆盖服务端建模，不引入第二几何栈。

## 3. 理由

- **人在回路架构延伸**（A-11）：微调是设计人员驱动的交互环节，本就走人工节奏；把它放在 gate2 之前，让「人审」作用于最终形态，审阅与交付版本一致，溯源链（A-02）从 A3 自动生成一路延伸到人工微调的每一轮。
- **复用最大化**：几何基建（cadquery 沙箱、geometry_inspect、IR3 版本链、GLB 版本缓存、WS 推送、LLM 供应商管理、多库检索上下文）全部已有；新增的只有微调会话域模型、工具调用协议与插件端改造。
- **诚实边界清晰**：一期不承诺参数化特征树编辑、不启动视觉自动校验（ADR-003 留观条件未触发）、插件内执行代码的安全边界如实写明（语法预检+快照+Stop 中断，非恶意防护）。

## 4. 后果与演进路线

- 正面：平台获得「生成→人工微调→定稿→审阅」完整闭环；微调全程留痕（轮次/脚本/FCStd/几何实测入 IR3 版本链）；插件状态与保存问题由平台存储根治。
- 代价：biz V10 两张表 + MinIO 新桶 `cad-tunes`；py-engine 新模块与 8 个端点；插件迁移改造一个迭代的工作量；设计机需安装 FreeCAD 1.x + 插件。
- **演进路线（承诺项，非本期范围）**：
  - 二期：FreeCAD 参数化特征树编辑（改尺寸约束不动拓扑；业界数据：参数级编辑解析准确率 96.3%，脚本路线鲁棒性约 1.4 倍差距）；
  - 二期：Web 端轻量微调（ModelTab 内点选+参数级修改，复用同一 cad_agent 服务端）；
  - 三期：视觉自动校验闭环（视 ADR-003 §2.2 重启条件）；商用 CAD 适配层（SOLIDWORKS/NX，文件级互通先行）。
