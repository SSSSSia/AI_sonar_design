# ADR-009: reference 实现一致性核查

| 项 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-10-09 |
| 触发 | 用户要求探索代码仓库，检查与实际实现冲突的地方 |
| 基线 | v0.7.0；当前 HEAD db24e54；同日文档整理 v1.1 |

## 发现

现行稿仍将部分目标写成已实现保证：审批冻结与导出门、全端点成员隔离、全链路单位拒绝、运营规则自动注入、三层记忆与生产网络约束。另有明确字段/配置错误：熔断 503 被写为 429、IR2 confidence 多列 low、覆盖率缺百分比单位、Gotenberg 内外端口混同。历史“7 条真实 LLM e2e”汇总也未区分测试自带 mock 的协议路径。

## 决策

1. 新增《实现一致性核查》，记录逐项代码依据、固定输入复核、实际边界及建议验收；区分文档错误与需要修改实现的欠账。
2. 定向订正 ARCH-001、TECH-001、WRITE-001、P2 底本与导航。目标需求保留，但不能作为当前已完成能力；原 archive 与本轮前快照继续零改动。
3. 审阅版本条件表述限于传入 expectedSnapshotVersion 的被审单份 IR；记录快照 ID 不等于冻结 IR2/IR3/IR4 整套版本。导出门、项目成员端点覆盖和单位处理盲区单独列为实现缺口，不用文字订正代替修复。
4. 固化 CSR/coverage 的百分比与计数范围；coverage=100% 不能替代 overall，也不能证明全量工程约束或真实 GJB 已验证。
5. 本轮仅修改文档；不修改业务代码、IR Schema、部署配置或 roadmap 完成状态。用户的核查要求授权本次定向文字订正，延续 ADR-007/008 的整理范围。

## 验证与后果

执行单位、校验状态、会话依赖和 CSR 的 4 份已有离线测试，37 项通过；固定输入复核确认 Schema 接受空来源/空 trace_id 与 null 值、拒绝 IR2 confidence=low，A4 公式结果比较仍取范围首数且未验证结果单位，coverage=100% 可与 incomplete 并存。复核使用内存夹具与空标准加载器，不访问业务库或 LLM。

历史验收报告保持原文并标记其日期；此次不是全系统、真实 LLM、FreeCAD 真机或生产安全验收。新增缺口没有被声明为修复完成。
