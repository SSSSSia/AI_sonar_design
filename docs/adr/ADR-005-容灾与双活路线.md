# ADR-005 · 容灾与双活路线（T11.7）

| 项 | 内容 |
|---|---|
| 状态 | 已定案（2026-10-01）；**实施触发条件 = 生产部署环境落地** |
| 关联 | GAP-001 §2.5 10.4 / P2-7、PHASE-011 T11.7、deploy/backup/（backup.sh / restore.sh / README） |

## 1. 背景

总体设计 §10.4 要求高可用与容灾。当前形态 = 单机 compose 开发栈（v0.4 已交付备份/恢复脚本 +
GraphML 快照 + 恢复演练）。双活（active-active / 流复制）在单机 compose 上无真实收益且成本高。

## 2. 备份基线（v0.4 已落地，deploy/backup/）

- PG：`pg_dump -Fc` 单库全量（权威备份），恢复 = `pg_restore --clean`；演练用临时容器零侵入。
- MinIO：五桶对象快照（py-engine 容器内 SDK 打包）+ 回灌脚本。
- Neo4j：在线 GraphML 快照（knowledge-dumps 桶留档）；严格一致性离线 dump（需停库）列生产项。
- Redis/RabbitMQ：RDB 拷贝 / definitions 导出（缓存与拓扑，低价值不追求 RPO=0）。

## 3. 双活路线（生产环境落地时按序实施）

| 层 | 方案 | 触发条件 | 说明 |
|---|---|---|---|
| PG | 流复制（1 主 1 从，同步提交 `synchronous_commit=on`）+ Patroni 自动切换 | 生产部署 | compose 单机不加；生产 K8s/多机时实施。应用侧连接串走读写分离代理 |
| MinIO | 4 节点纠删码 + 站点复制（site replication） | 多机部署 | 对象级双向复制，RPO≈0 |
| Neo4j | Causal Cluster（3 核心）或定时 GraphML/dump 异地快照（当前形态延伸） | 生产部署 | 读扩展主用途；备份恢复优先于集群化（成本） |
| Redis | 主从 + Sentinel | 生产部署 | 缓存可重建，最低优先级 |
| RabbitMQ | 镜像队列 / quorum 队列 | 生产部署 | 任务消息；已有 DLQ 与 acks_late 语义 |
| 应用层 | py-worker 多副本（队列天然扇出）+ Java 服务多实例（gateway 负载均衡） | 生产部署 | 无状态，水平扩展即可 |

## 4. 决策

1. **v0.4 只做备份/恢复落地 + 本方案文档**（用户确认）；流复制/集群不实施。
2. 双活实施顺序（生产时）：PG 流复制 → 应用多副本 → MinIO 纠删码 → Neo4j 集群 → Redis/RMQ。
3. 备份是双活的前置而非替代：任何集群形态下 backup.sh 仍保留（逻辑备份可跨版本恢复）。
4. Neo4j 备份当前为在线 GraphML 快照（快照语义如实）；生产补充离线 dump 全一致性检查点。
