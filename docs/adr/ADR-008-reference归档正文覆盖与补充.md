# ADR-008: reference 归档正文覆盖与补充

| 项 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-10-09 |
| 触发 | 用户要求再次检查已归档文档还有哪些内容遗漏 |
| 基线 | v0.7.0；延续本轮文档 v1.1，不新增软件能力 |

## 发现

逐章对照五份历史稿后，图件之外仍有值得保留的 Agent 内部方法、检索充分性补查目标、多段 CAD 范例、缓存失效纪律、中间交付物与合作资料要求。原方案部分目标没有实现证据，不能因“恢复原文”变成已实现承诺。

现行稿还存在遗留偏差：E1 依赖字段与实际会话内现算图不同；Origin Lock 被描述成已实现原子锁；任务时限沿用历史 15/20 分钟而配置默认是 30/40 分钟；环境变量配置被等同于免重启热更新；P2 示例接口、生产目标没有充分标记身份。

## 决策

1. 新增《归档正文覆盖与补充审查》，逐章登记来源、现行落点和处置理由；与 FIG-AUDIT-001 的 17 张历史图清单互补。原 archive 根目录与整理前快照继续零改动。
2. 在 ARCH-001 恢复 C1–C5 对应 A1–A5 的职责、输入/输出、内部步骤、边界；正式 IR 字段以 contracts/ir 为准。能力编号可用于说明，与 E1–E3 合成八项能力，不作为新的服务/部署划分。
3. 在 TECH-001 补多段 CAD 方法、A1 证据充分性目标、缓存 TTL/失效规则、有界终止及求解覆盖边界；待补查能力只列设计目标，不改 roadmap 进度。
4. 在 WRITE-001 恢复中间产物的写作映射、合作资料输入与验收设计建议；不承诺独立声学计算书、全自动语义批注路由、全量军标及企业系统对接已落地。
5. 定向修订 P2 对应参数字段、配置、API/集成目标说明，与两份 P1 保持一致；历史附录 E 原文保留，由本轮说明指出差异。用户本轮检查与补齐要求覆盖 ADR-006 对底本文字冻结的旧维护纪律，补充 ADR-007 的定向修订范围。
6. 以代码修正 E1 抑制语义：paused@gate2 的正向入口、来源记录、正向变更链深度上限 3、反向提案人工确认；不宣称已验证并发原子互斥。公式依赖遍历的深度保护 10 是另一机制。D08 同步改标注、重新导出并更新指纹。
7. 超时按执行路径分别说明；CadQuery 默认 300s、LLM 默认 300s、任务登记默认 1800/2400s。当前 Compose worker 为 solo，配置登记不等于本轮证明任务软/硬超时强杀有效；环境变量读取不是自动热更新。未运行的新验收不写为通过。

## 后果

原稿中的有价值方法可继续用于申报和论文；过时方案保留可查出处，待补功能有明确身份。P0 权威次序和硬约束、IR Schema、业务代码、运行配置、软件版本与任务进度均不变。本轮文档版号仍为同日整理 v1.1，修订记录同时标注 ADR-007/008。
