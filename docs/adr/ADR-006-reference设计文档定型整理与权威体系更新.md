# ADR-006: reference 设计文档定型整理与权威文档体系更新

| 项 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-10-08 |
| 决策人 | 用户（申报/毕业论文写作需求驱动） |
| 关联 | 宪法 CONST-001 §1.1（本次修订 v1.2）、`docs/reference/README.md`、`docs/reference/archive/README.md` |

## 背景

`docs/reference/` 存放项目自身六份多代系统设计文档（源自 Sonar_cad_design 旧仓库迁移），其中五份已被书面取代：互相大段重复、口径过时（二代为单后端 FastAPI 口径、建议书含已弃用自造术语）。项目进入**项目申报与毕业论文写作**阶段，写作时在多代口径间取材易误用旧叙事（如"两道审阅关""单后端"），需要一套**以实际实现为准**的定型架构与技术方案文档作为单一可信出处。

## 决策

1. **新增三份定稿**（存放 `docs/reference/`，头部标注版本 v1.0 / 定稿日期 / 口径基准 v0.7.0）：
   - 《系统总体架构定稿》：五层架构、服务拓扑、核心业务流、IR0–IR5 契约、数据底座、部署拓扑、横切能力、决策索引；
   - 《技术方案定稿》：技术栈总表、九项关键技术路线、性能与可靠性指标、测试资产、安全合规、边界与欠账；
   - 《申报与论文写作指引》：创新点提炼、技术指标汇总、论文架构章大纲映射、申报段落模板。
   - 编写口径：**以 v0.7.0 实际实现为基准**，《总体设计方案》作叙事骨架；每个架构/数字事实带出处（代码路径或文档章节），可验证、可答辩。
2. **归档五份被取代代际**：`git mv` 至 `docs/reference/archive/`（内容零改动），新增 `archive/README.md` 记录各文档代际、取代链与使用边界。
3. **宪法 §1.1 权威优先级重排**：P0 宪法不变；P1 = 两份定稿；P2 = 《总体设计方案》（完整设计底本）；P3 = `archive/`。正文 P 编号引用同步更新（§2 决策表依据列 P3→P2、§3/§7 各处）。
4. 《总体设计方案》仅附录 E.4 追加 v0.7 状态行（沿用 2026-09-30 起的"仅 E.4 允许追加"纪律）。

## 影响

- **正面**：申报/论文素材有了单一可信出处；`docs/reference/` 语义清晰化为三层（定稿 / 权威底本 / 归档）；宪法权威体系与现实一致（旧 P1/P2/P4 均为已归档文档，原编号已失锚）。
- **风险与缓解**：宪法 P 编号变更可能遗漏外部引用 → 全库 grep 五个归档文件名与 `P3 §` 引用逐一核对（devlog 与历史记录中的旧路径属历史记录不改）；定稿存在口径漂移风险 → README 维护纪律约定重大版本收官时同步复核。
