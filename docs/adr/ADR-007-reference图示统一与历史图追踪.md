## 背景与核验

ADR-006 整理后，完整底本仍保留编制时图示，定稿图也存在知识关阻塞完成、驳回目标过窄、部署数量与事件通知口径错误。历史五稿共 17 张 Mermaid 图仍在 archive，定稿没有保留 Agent/IR/时序等独立视图，写作取图容易混用设计目标与实现事实。

## 决策

1. P0/P1/P2/P3 权威顺序及代码实现不变。以代码核验修正文档：A1–A5 在 py-engine，workflow 负责固定顺序调度；A3 完成后才执行 A4；gate2 在 IR3+IR4 之后；knowledge 在 completed 后确认回写，属于第三个人工确认点但不是 paused 管线关。
2. 每个现行视图赋固定图号 D01–D15，在 reference/diagrams/*.mmd 维护唯一图源。当前 Markdown 内的带标记图由 scripts/reference_diagrams.py 同步，禁止维护多份手工变体。统一字体、颜色、节点和连线语义。
3. 新增图示总册、逐图追踪表与 SVG 导出。补回历史稿有价值的 Agent 拓扑、IR 数据依赖、编排时序、存储职责和页面流程，按当前实现重绘；过时单后端/四层架构/生产集群蓝图保留历史身份，不冒充现状。
4. 本轮用户要求优先于 ADR-006 中“底本正文一字不改”的维护纪律：允许定向修订完整底本的五张图及紧邻说明、架构/技术选型/审阅/部署段落；其需求、功能、远期目标与历史增补继续保留并明确时间身份。修改前五份当前文档完整复制到 archive/review-2026-10-09，SHA-256 登记。本轮不修改原有 archive 根目录任何文件；CONST-001 仅同步 P2 版本引用及版本登记为 v1.3，不修改开发硬约束。
5. 修正三个写作素材的图号和计数、知识确认语义、六类 WS 消息与容器统计。去掉缺少比较研究支撑的“国内多数/首次”等创新性断言及“一切数值都由代码产生”的过宽描述；公式类参数的确定性计算边界不变。

## 后果与维护

同一视图在不同文档中保持逐字一致；不同图分别解释逻辑分层、运行部署、控制流与数据依赖。当前 Compose 定义为默认 10 项（含一次性初始化）+ app 9 项 + monitoring 6 项，另有 loadtest 1 项；不能把宿主机全部 29 个容器当项目服务数。知识候选生成完成与知识回写批准独立表达。

复核命令：python scripts/reference_diagrams.py --check。架构/数字变更时先核验来源，再改唯一图源并同步文档，记录 devlog。渲染与快照完整性结果见 reference/图示一致性与历史图追踪.md。

## 同轮图形表达修订（用户反馈）

D04 明确沿用 archive《设计方案》图 4-2 的固定管线 + 横切服务 + 底座表达和服务分组配色。主线 IR 箭头是经 workflow 的逻辑接力，不是 Agent 直接互调。D02 展示真实通信，D03 展示审阅控制，D05 展示完整数据依赖，避免用任务派发星状图替代用户认可的 Agent 拓扑。架构硬约束与实现不变。
